# 写正文：结构、标题层级、题注、内容来源

> **先读这条**：本文里的「图表」「参考文献」「代码」都是**条件项**——
> 报告有没有这些，由**用户要求 → 指导书 → 模板**逐级决定，都没有就不做。
> 详见 SKILL.md 开头的需求从哪来。

## 一、小标题层级

按下面的顺序递进，**一层用完再用下一层**：

| 层 | 形式 | 用途 |
| --- | --- | --- |
| 1 | `1.` `2.` `3.` | 一级小标题 |
| 2 | `(1)` `(2)` `(3)` | 一级下面的细分 |
| 3 | `①②③` | 再细分 |
| 4 | `1.1` `1.2` … `2.1` `2.2` … | 前面都用完了才用 |

**层级格式随模板**：模板把小标题做成加粗+黑体，就照着做；模板没有区分标题层级，就用正文同款字体只加粗。

注意不要和模板已有的大节编号（`一、` `二、` `四、`）混在一起——那些是模板写死的，你只负责它下面的内容。

## 二、题注

### 格式

固定为 **`图 3 名称`** / **`表 2 名称`**：

```
前缀 ─ 空格 ─ 编号 ─ 空格 ─ 名称
```

- 无论名称是中文打头还是英文打头，**空格数完全一致**——统一用半角空格，前后各一个。
- 名称简明描述内容即可，末尾不加标点。

### 编号用域，不要硬编码

用 `SEQ` 域自动编号，外面套书签供正文引用：

```python
caps = K.Captions()
caps.declare('fig_topo', '图')                  # 第一遍：按最终出现顺序登记
...
cur.put_image('pics/topo.png', 400)
cur.put(K.caption(caps, 'fig_topo', '实验网络拓扑'))
```

正文里写 `<<fig_topo>>`：

```python
cur.put(K.body(caps, '网络拓扑如<<fig_topo>>所示，各端口分配见表<<tab_host>>。'))
```

渲染结果："网络拓扑如**图 1**所示，各端口分配见表 **1**。"——编号是引用关系，中途插删图表后会跟着变。

**为什么要两遍法**：正文里"如图 4 所示"很可能出现在图 4 *之前*。一边写一边编号必然串号。先全部 `declare` 再渲染，就没有这个问题。

### 模板原有的图/表不动

模板里已经有的图或表：**不加题注、不改编号、不参与交叉引用**。你的编号从 1 开始，只统计你自己插入的图表。

### 位置

- **图注在图下方**，**表注在表上方**。
- 图和题注必须在同一页（见下）。

## 三、图与题注同页

图跑到上一页、题注留在下一页，是最常见也最容易失分的排版错误。

```python
cur.put_image(path, 400)                       # 图片段落自带 keepNext
cur.put(K.caption(caps, 'fig01', '...'))      # 紧跟其后
```

题注段落也带 `keepNext`，两者形成一条"不许分开"的链。

表格没有 `keepNext` 可用，所以要用无边框 1×1 表格把"表题 + 表格"包起来（`K.wrapped_table` 就是这么做的），让 Word 把它们当整块挪动。

## 四、正文写法

### 内容来源

报告正文来自：**实验指导书 / 任务书 + 模板 + 用户给的图片和数据 + 联网检索**。

### 不要出现"太基础"的废话

"打开 VMware""双击图标""登录系统"这类操作流水账，**默认不该出现在报告里**。报告要写的是**做了什么、观察到了什么、为什么是这样**，不是把动手过程复述一遍。

**不要试图按年级去猜这个尺度。** 年级不是判断依据，按无关处理：

- 默认**从简**——一句话带过环境准备，把篇幅留给结果与分析；
- 指导书明确要求"记录操作步骤"时照做；
- **只有确实影响到该怎么写、又判断不出来时**，才问用户一句（例如"这门课要不要交代虚拟机的搭建过程"），问完就按答复写，别再纠结年级。

宁可少写流水账，也不要让整篇报告读起来像操作手册。

### 代码怎么放

| 情况 | 做法 |
| --- | --- |
| 用户提供了**代码截图** | **用截图**——有语法高亮，版面也省 |
| 没有截图 | 自己生成**文本块**：Consolas 小一号 + 灰底 |

```python
cur.put(K.code_block('''$ ./build.sh --target release
[ 45%] Compiling module net
[100%] Build finished: bin/app (2.4 MB)'''))
```

文本块可以复制、可以检索，老师查重和核对时体验更好，所以没截图时优先用它而不是自己截图。
过长（超过一屏）的代码考虑只贴关键片段——报告要的是**说明问题**，不是代码存档。

### 文献引用

正文引用了文献就要标上标序号，文末列参考文献表。完整规范见 `citations.md`。

### 结果分析要有信息量

配了截图的段落，要做**字段级解读**，而不是复述：

- 差：`如图所示，可以看到报文的各个字段。`
- 好：`该帧总长 98 字节——把它各层头部的长度加起来恰好也是 98 字节，与帧头声明的总长相符，说明解析没有偏差；再由匹配域为空这一点，可以确认设备执行的是兜底转发分支。`
- 好在哪里：**做了核对**（加总 vs 声明值）、**下了结论**（走的是哪条分支），而不是描述"图里有什么"。

具体做法：

- 读数、算差值、做核对（长度对不对、计数累加对不对）；
- **对比**两个截图（"与图 X 相比，新增了……"）；
- 指出反常之处并解释（"首包时延 4.2 ms 远高于后续的 0.25 ms，这是控制平面介入的代价"）；
- 把字段值翻译成它代表的行为。

### 拿不准的地方要标注

数据不全、现象无法解释时，写"需进一步验证"而不是编一个解释。**不编造实验数据**。

## 五、学术诚信

**用户提供了同课程的成品报告时，它只用于两件事：**

1. **格式迁移**——它的标题层级、字体字号、题注写法；
2. **结构参照**——它分了哪几节。

**绝不能复制粘贴文字。** 所有正文必须基于指导书、模板、用户提供的材料和自己检索的结果重写。

同理，也不要把往届报告改头换面当成新报告——即便换了措辞，实验数据、分析结论照搬同样属于抄袭。
