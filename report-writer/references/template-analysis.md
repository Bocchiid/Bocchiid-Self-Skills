# 解析模板：框、可编写区域、格式

## 一、先搞清楚"框"是什么形态

模板一旦被写坏——框被撑破、评分表被塞进正文、页眉页脚丢失——整份报告就废了。
所以这一步的目标不是"找到框"，而是**在不破坏模板的前提下确定往哪写**。

### 为什么不能靠自动识别

"留给你填写的区域"至少有四种形态，实测都遇到过：

| 形态 | 表现 | 例子 |
| --- | --- | --- |
| **① 单列长表** | 内容自上而下堆在一列里，某几行留空 | 表格只有 1 列，7~12 行 |
| **② 多列表单** | 每行是一个栏目：`标签｜填写区` | `问题介绍｜注：此栏目用于…` |
| **③ 正文区 + 评分表拼在一张表里** | 同一张表前半是填写栏，后半是打分表 | 前 6 行是填写栏，第 7 行起是"教师评价" |
| **④ 纯段落结构** | 压根没有表格，正文写在一串段落里 | 靠"主要内容："这类锚点定位 |

**只有 ① 能可靠自动识别。** 其余三种任何启发式都会在某一门上猜错，
而猜错的代价是**静默地把正文写进评分表**——比找不到更糟。

⚠️ **判断列数必须用去重后的格数。** python-docx 的 `row.cells` 会把横向合并的
单元格重复返回，一张 2 列的表能被算成 9 列。判断"是不是单列"要用
`docx_kit._effective_cols()`（内部按 `w:tc` 去重），不要用 `len(table.columns)`。

### 四步流程

```
勘察 survey()  →  显式指定 Target  →  写入前 check()  →  写入后 finish() 比对
```

绝不能跳过任何一步。

## 二、第一步：勘察

```python
import sys; sys.path.insert(0, 'scripts')
from docx import Document
import docx_kit as K

d = Document('模板.docx')
print(K.survey(d))
```

`survey()` **不做判断，只摆事实**：每张表的行列数、有无边框、每行的标签与字数，
并标出「近乎为空」的格子和「疑似评分表」。

```
文档勘察：4 个顶层段落、2 张顶层表格

TABLE[0]  3行 × 2/4/6列  无边框
    row0   5字「实验名称：」 | 13字「实验一 Linux编程环境」   ⬅ 近乎为空
    row1   7字「班    级：」 | 0字(空) | 6字「姓   名：」 | 0字(空) …   ⬅ 近乎为空

TABLE[1]  7行 × 1列  无边框  单列长表（可被 find_frame 自动识别）
    row0   61字「一、实验目的：1、掌握vim编辑器的使用2、」
    row4   254字「五、实验结果与分析（含程序、数据记录及分析和…」
    row6   7字「七、教师评语：」
```

**怎么读这份勘察：**

- `× 2/4/6列` 表示各行格数不一致 —— 这是**合并单元格**造成的，实际是"表单 + 合并块"。
- **结构固定、带冒号标签的格子**（`实验名称：`、`姓　名：`）多是封面信息，不是正文区。
- 标着 **⬅ 近乎为空**、或只有一句"注：此栏目用于…"占位说明的格子，才是留给你的。
- 标着 **⚠️ 疑似评分表** 的表，**任何情况下都不要往里面写正文**。

### 没有表格时

`survey` 会直接说明这是**段落式模板**，并提示用锚点定位。这类模板的正文区
通常在某个提示句之后——找出那句提示（如 `主要内容：`、`（正文不少于2000字）`）
作为锚点。

## 三、第二步：显式指定写入目标

**不要猜，直接指名。** 三种形态对应三种 `Target`：

```python
import docx_kit as K

K.Target.cell(table=1, row=3, col=0)   # 往 TABLE[1] 的 row3 追加（形态 ①②③）
K.Target.after('主要内容：')            # 在含该文字的段落后插入（形态 ④）
K.Target.at_end()                      # 追加到文档末尾
```

`find_frame(doc)` 仍然可用，但它**只返回单列长表**（形态 ①），认不出来就返回空列表。
它是在替你守着"宁可让你去指定，也不要猜一个出来"这条线——**看到它返回空，
不要去凑合选一个多列表，去 `survey()` 里自己找。**

## 四、第三步：写入前检查（**强制自动**）

```python
cur = K.Cursor(doc, K.Target.cell(1, 3), keep_paras=1)
cur.put(K.heading(1, '1. …'))     # ← 首次 put() 自动跑检查，拦到就抛错
```

**不需要你记得调用**——`check_target()` 在第一次 `put()` 时自动执行。
拦下时**文档一个字节都没动**（清空目标格推迟到检查通过之后），
中途放弃不会留下半个被清空的模板。

确实判断是误报时显式放行，且**必须给理由**：

```python
cur.force('人工确认这里是自评栏，允许写入')   # 不给理由直接报错
```

`check()` 拦两类真正的危险：

| 拦截 | 判据 | 为什么危险 |
| --- | --- | --- |
| **目标落在评分/评价行** | 目标行及其上方 3 行内含 ≥2 个评分类关键词（评价/赋分/得分/评分/考核/成绩…） | 往评分表里塞正文，交上去就废了 |
| **目标格已有相当多内容** | > 60 字 | 那多半是模板原有内容，写进去就覆盖了 |

评分判断是**按行**做的，不是按表：有的模板把"填写栏"和"教师评分表"做在同一张表里，
整表判断会误伤前半部分。

`keep_paras` 控制清空目标区时保留几段（通常是 1——留住模板本来就有的那句
"四、基础实验步骤与结果："）。

## 五、第四步：写入后比对

```python
cur.put(K.heading(1, '1. …'))
cur.put(K.body(caps, '……'))
report = cur.finish()
```

`finish()` 比对写入前后的**表格结构指纹**（每张表的行数、每行格数、每格字数、有无边框）。

正常时只报目标格：

```
['TABLE[1] row3 各格字数 [12] → [480]']
```

出现别的条目就是模板被动过了：

```
['TABLE[1] 行数变了：5 → 4']              ← 表格结构被破坏
['TABLE[0] row2 各格字数 [4, 18] → [4, 16]']   ← 动了不该动的格子
```

**这一步不依赖任何猜测**，是模板安全的最后一道闸。它抓的是结果，不是意图——
前面几步都判断对了它报平安，前面判断错了它也能把事故拦在交付之前。

## 六、提取"需编写区域"的格式

**只提取要写的那块，不要动模板其余部分。**

要看的：

| 项 | 在哪看 |
| --- | --- |
| 字体、字号、加粗、颜色 | 该单元格里**模板自己写的**段落的 run |
| 段落样式名 | `w:pStyle`（如 `Caption` 题注样式） |
| 首行缩进 | `w:ind firstLineChars` / `firstLine` |
| 段前段后、行距 | `w:spacing` |
| 标题层级风格 | 小标题是加粗？黑体？放大？还是跟正文同款 |

**关键：拿模板自己已有的段落当基准，别拿自己的第一版当基准。**

### 只对齐"需编写区域"

模板里的封面、评分表、已有的实验目标——这些都不需要你写，它们的格式**原样跳过**。写一份报告不需要让整篇文档风格统一，只需要让**你写的那部分**贴合模板。

### 段前段后不要自己加

插入的段落不要带 `w:before` / `w:after`，让它继承 Normal 样式。写了显式间距，用户一眼就看出来"这不是模板的样式"。

## 七、模板里放的是"格式说明"时

有些模板的正文不写内容，写的是：

```
正文              宋体 小四 1.5倍行距
二级标题          黑体 四号
图表题注          宋体 五号 居中
```

或者干脆是"正文字体 XXX、字号 XXX"这样的说明。

**这种情况严格照它说的做**——比任何推测都权威。照做之后在交付说明里点一句"按模板中的格式说明设置"，方便用户核对。

## 八、样式名不要想当然

**同样是"实验报告模板"，不同实验的模板可能完全不同。**

实际遇到过的：一个模板里 `Caption`（题注）是段落样式、`styleId="a4"`；另一个模板里 `a4` 是**字符样式**「页眉 字符」，根本没有 `Caption` 段落样式。照抄前一份报告的 `pStyle` 值就会静默套错样式，而且不一定报错。

动手前先列样式表：

```python
for s in doc.styles:
    print(s.style_id, s.type, s.name)
```

要用的样式不存在时，往 `d.styles.element` **追加**一个（只增不改，不破坏模板），同时给每个 run 写上显式字体字号——这样即使样式被丢弃，外观也不会变。

## 九、老式 `.doc` 模板的处理

python-docx 打不开 `.doc`，先转：

```bash
powershell -File scripts/word_com.ps1 -Action to-docx -In 模板.doc -Out work.docx
```

编辑完再转回去：

```bash
powershell -File scripts/word_com.ps1 -Action to-doc -In out.docx -Out 报告.doc
```

⚠️ `.docx` 存回 `.doc` 会丢一些元数据（`w:rFonts w:hint="eastAsia"`、`w:tblInd`、几个样式定义被重新规范化）。这些**不可避免且不可见**，不要试图消除。

判断"模板有没有被我破坏"的正确方法：把原始模板也走一遍同样的往返，比较两者的 XML 差异集合；**差异集合一致**即视为没破坏，而不是要求差异为零。

`w:trHeight`（框每行的最小高度）是**会**保留的——如果框的行高明显丢了，那才是真的把表格重建了。

## 十、记下交付格式：跟模板走

解析模板时顺手把**扩展名**记下来，它决定最终产出什么：

| 模板 | 交付 |
| --- | --- |
| `xxx-模板.doc` | **必须**产出 `.doc` |
| `xxx-模板.docx` | 产出 `.docx` |

中途为了用 python-docx 编辑，`.doc` 会先转成 `.docx` —— **但那份 `.docx` 只是中间产物，不是成品**。交付前一定转回去：

```bash
powershell -File scripts/word_com.ps1 -Action to-doc -In out.docx -Out 报告.doc
```

格式和模板不一致，老师那边很可能打不开或者版式错乱，这是很低级的失分点。

## 十一、工作目录

**所有中间产物写在报告所在目录下**——工作副本 `work.docx`、构建脚本 `build.py`、压缩后的图片副本、导出的 `preview.pdf`。用户一眼能看到全过程，相对路径也不会突然失效。

只有确实遇到绕不过去的权限问题（目录只读、被同步盘锁住）才退到系统临时目录，并在交付时说明中间产物放在哪。

解析完模板，确认这几件事再动手：

- [ ] **写入目标已显式指定**（`Target.cell(...)` / `Target.after(...)`），没有依赖自动猜测
- [ ] `Cursor.check()` 返回空 —— 没有指向评分行、也没有指向已有内容的格子
- [ ] 已记下要写区域的字体、字号、样式名、缩进
- [ ] 已列出模板的样式表，确认要用的样式确实存在
- [ ] **已记下模板的扩展名（`.doc` / `.docx`），交付时按它产出**
- [ ] 写完 `Cursor.finish()` 的比对报告里**只有目标格**有变化
