# 审核发现的路由

## 为什么需要 triage

审核报告是自然语言，可能误报、重复、指向错误。直接把每条都丢给 writer 改，会：
- 改坏本来正确的内容；
- 为了“清零”删掉有信息量的分析；
- 反复修同一个问题，轮次烧完。

triage 的职责：**先核实，再分派，只重跑受影响的下游。**

## 核实四问

1. 位置存在吗？（章节/段落/图号）
2. 报告原文真的有问题吗？
3. 依据成立吗？（要求/模板/证据/数据）
4. 当前材料范围内能修吗？

任何一项不成立 → 标 `需人工复核`，不自动修。

## 分类

| 审核发现 | 责任方 | 下一步 |
| --- | --- | --- |
| 数据/结果错误、实验没做对 | operator | `EXECUTE` |
| 截图缺字段/模糊/对应错步 | operator/evidence | `RECAPTURE` |
| 正文分析浅、缺要求、表述错误 | writer | `WRITE` |
| 格式/题注/引用/版面/模板保护区 | writer | `WRITE` |
| 计划缺步骤/证据/目的未覆盖 | planner | `PLAN` |
| 需求冲突/无法判断 | human | `WAITING_USER` |
| 只有建议/可选 | none | `DONE` |

## 重跑范围

| 改动 | 重跑 |
| --- | --- |
| 只补一张截图 | `RECAPTURE → EVIDENCE_REVIEW → WRITE → REVIEW` |
| 只改报告格式 | `WRITE → REVIEW` |
| 改了一节分析 | `WRITE → REVIEW` |
| 实验数据错了 | 受影响步骤 → 证据 → writer → reviewer |
| 计划缺步骤 | planner 升版 → 用户确认 → 受影响步骤 |

不要因为一张图重做整个实验；也不要因为改一句重跑所有步骤。

## 收敛

- 同一问题连续 2 轮仍在 → `BLOCKED`，让用户决定；
- 新一轮出现旧轮没有的阻断 → 回归，回对应责任方；
- 报告轮次达到上限 → 停，列出剩余问题；
- 建议/可选不阻塞；不要为了“完美”无限循环。

## triage.json 示例

```json
{
  "round": 2,
  "items": [
    {
      "id": "T1",
      "source": "审核报告 五、结果分析 第2段",
      "problem": "未解释丢包异常",
      "verified": true,
      "owner": "writer",
      "action": "补充异常原因与排查过程",
      "rerun": ["WRITE", "REVIEW"],
      "severity": "建议"
    }
  ],
  "needs_human": [],
  "blocked_reason": ""
}
```

## 常见误报

- 把“用户说明的实际差异”判成错误 → 不修，单列差异；
- 把“模板预填内容”算成学生问题 → 不修；
- 把“条件项没要求”判成缺项 → 不修；
- 把“正文末页不满”判成排版问题 → 不修；
- 把“建议”当“阻断” → 不阻塞。

## 禁止

- 为了让分数好看删掉正确内容；
- 跳过用户确认改实验目的/交付要求；
- 同一问题修超过 2 轮；
- 不核实就按 reviewer 的话改。
