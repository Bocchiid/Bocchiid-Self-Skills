# 跨学科示例

示例只展示**规划思路**，不是标准答案；默认产出格式见 `execution-card-template.md`。
实际步骤以用户描述为准。

---

## 示例 1：网络设备配置（操作验证型）

**任务**：VLAN 划分与跨 VLAN 路由。

**用户描述与指导书差异**：指导书用三层交换机；实验室只有二层交换机 + 路由器，
老师口头改为"单臂路由"。

**规划要点**：

- 差异表：设备、拓扑、配置命令都按实际写；报告"实验环境"写实际型号。
- 目的核对：VLAN 划分、Trunk、跨 VLAN 通信三条目的仍能覆盖；原"三层交换"目的
  标为"由单臂路由替代"，问用户老师是否接受。
- 步骤：
  - S1 记录交换机/路由器型号、系统版本、拓扑（E1）
  - S2 配置 VLAN 10/20，划分接口，保存（E2）
  - S3 配置 Trunk 与子接口/单臂路由（E3）
  - S4 验证同 VLAN 通、跨 VLAN 通、ACL/断开时不通（E4、E5）
  - S5 导出配置/日志，记录失败与回退（E6）
- L1 证据：环境版本、`show vlan brief`、Trunk 状态、路由子接口、ping 成功/失败对比。
- 报告映射："实验环境"用 E1；"实验步骤"用 E2/E3；"结果分析"用 E4/E5 解释
  "为什么同 VLAN 通、跨 VLAN 初期不通、加了网关后通"。
- 常见坑：只截配置页不截验证；截图看不到接口名/设备名；没记录失败现场；
  报告里写"三层交换机"但实际是路由器。

## 示例 2：套接字文件传输程序（编程实现型）

**任务**：基于 TCP 流式套接字实现文件传输，要求支持大文件和异常断开。

**规划要点**：

- 步骤：
  - S1 明确协议：文件名、长度、分块、结束标志（E1 设计说明）
  - S2 环境：语言/库版本、编译命令、目录结构（E2）
  - S3 实现最小可用版本：单文件、小文件（E3 代码 + E4 运行输出）
  - S4 补大文件/分块/进度/异常处理（E5 关键代码）
  - S5 测试：正常、空文件、大文件、对端断开、路径不存在（E6 测试表）
  - S6 记录一个真实 bug 的发现与修复（E7 报错 + 修复前后）
- L1 证据：目录结构、关键代码、运行命令与输出、测试用例表、失败/修复记录。
- 报告映射："设计"用 E1；"实现"用 E3/E5；"测试"用 E6；"问题与解决"用 E7。
- 常见坑：只贴代码没有运行结果；代码与报告命令不一致；没有边界测试；
  大文件测试只写"成功"没有耗时/完整性校验。

## 示例 3：电子商务现状调查（调查调研型）

**任务**：调查电子商务现状、三位领域人物、AI 漫剧盈利模式与趋势预测。

**规划要点**：

- 步骤：
  - S1 拆研究问题：概念、趋势、人物、盈利模式（E1 问题清单）
  - S2 检索行业报告/平台数据，记录来源、年份、URL（E2）
  - S3 收集三位人物公开资料，每人至少 2 个可靠来源（E3）
  - S4 拆 AI 漫剧盈利模式：分账、付费、广告、IP 衍生、品牌定制、出海（E4）
  - S5 用数据支撑预测：市场规模、增长率、爆款率、用户规模（E5）
  - S6 整理引用与来源清单（E6）
- L1 证据：报告封面/关键数据页 + URL + 日期；人物资料来源；盈利模式页面；
  数据表/图表；引用清单。
- 报告映射："概念"用自己的话 + 来源；"趋势"用 E2/E5 数据；"人物"用 E3；
  "盈利模式"用 E4；"结果分析"区分事实、推断、个人判断。
- 常见坑：只写观点不标来源；数据没有年份；把网上一篇文章当权威；
  1000 字全是罗列没有分析；预测没有数据依据。

## 示例 4：创新创业商业计划书（设计策划型）

**任务**：3~4 人小组，从校园场景出发写一份商业计划书。

**规划要点**：

- 步骤：
  - S1 确定问题与目标用户：校园里什么需求没被满足（E1 访谈/观察记录）
  - S2 需求验证：至少 10 份问卷/5 个访谈，记录样本与结论（E2）
  - S3 方案构思：至少 2 个方案（E3 方案草图/原型；报告里的流程图/架构图由 writer 绘制）
  - S4 方案对比：需求匹配、成本、时间、风险、合规（E4 对比表）
  - S5 商业模式：收入来源、成本结构、定价、获客（E5 商业画布）
  - S6 市场与竞争：规模、竞品、差异化（E6 竞品截图/数据）
  - S7 可行性：技术、经济、运营、法律（E7 预算/进度/风险表）
  - S8 分工与个人贡献（E8）
- L1 证据：访谈/问卷原始记录、方案草图、对比表、商业画布、预算/进度、竞品资料。
- 报告映射：背景→需求→方案→对比→商业模式→可行性→团队分工；
  每一节都要有证据，不能只写设想。
- 常见坑：只有一个方案；目标用户空泛；财务数据拍脑袋；把"设想"写成"已实现"；
  小组分工写成"大家都参与"。

## 示例 5：文化类课程田野观察（体验观察型）

**任务**：参观本地非遗工坊，写一份观察报告，结合课程中的文化传承概念。

**规划要点**：

- 步骤：
  - S1 准备：联系工坊、确认拍摄许可、列观察提纲（E1 提纲/许可记录）
  - S2 现场记录：时间地点、工艺流程、传承人原话、环境细节（E2 笔记）
  - S3 拍照：全景 + 关键工艺细节 + 作品（E3，需同意）
  - S4 当天整理：补笔记、标注不确定信息（E4）
  - S5 补充资料：工坊历史、非遗政策、相关研究（E5 来源清单）
  - S6 分析：工艺特点、传承困境、与课程概念的对应（E6 分析框架）
  - S7 反思：观察偏差、样本限制、个人收获（E7）
- L1 证据：观察提纲、现场笔记、照片（如允许）、受访者原话（匿名）、
  背景资料来源、同意/匿名说明。
- 报告映射："观察记录"用 E2/E3；"分析"用 E6 对应课程概念；
  "反思"用 E7；"参考文献"用 E5。
- 常见坑：只写感受不写事实；记录笼统；照片涉及他人未同意；
  把网上资料写成现场观察；时间地点对不上。

## 示例 6：课程项目（项目综合型，多人）

**任务**：网络系统设计课程项目，4 人小组，需提交课程报告并体现个人贡献。

**规划要点**：

- 步骤：
  - S1 需求与验收标准（E1）
  - S2 调研与方案对比：至少 2 套架构（E2）
  - S3 分工与进度：WBS、里程碑、个人负责模块（E3）
  - S4 实施：版本记录、会议纪要、关键决策（E4）
  - S5 测试/验收：测试用例、缺陷、修复（E5）
  - S6 个人总结：我负责什么、产出是什么、与别人的接口（E6）
- L1 证据：需求文档、方案对比表、分工表、提交记录、测试记录、个人产出文件。
- 报告映射：项目概述→需求→方案→实施→测试→个人总结；
  个人贡献要能对应到具体文件/模块/章节。
- 常见坑：分工无法验证；进度表事后编；个人总结写成团队总结；
  只写成功不写问题；小组内容雷同。

## 示例 7：文献分析/读书报告（案例文献型）

**任务**：某门通识/文化课程要求读 3 篇文献，围绕一个主题写分析报告。

**规划要点**：

- 步骤：
  - S1 界定问题与范围（E1 问题陈述）
  - S2 检索：关键词、数据库、筛选标准（E2 检索记录）
  - S3 阅读笔记：每篇的核心观点、证据、方法、局限（E3 笔记）
  - S4 建立分析框架：比较维度/理论视角（E4 框架图）
  - S5 论证：观点 + 证据 + 反例/限制（E5 引用对照表）
  - S6 结论与参考文献（E6）
- L1 证据：检索式与结果、文献清单、关键原文摘录/页码、分析框架、引用对照。
- 报告映射："问题"→"文献综述"→"分析"→"结论"；每段观点都要有出处。
- 常见坑：只罗列摘要；引用无页码；百科当权威；观点与材料脱节；
  大段引用不加引号；参考文献格式混乱。
