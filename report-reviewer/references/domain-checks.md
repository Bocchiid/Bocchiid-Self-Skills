# 学科领域检查规则

> 以下是示例规则，按任务形态取用，不限于这些学科；没有对应领域时按通用检查项审。

## 操作/理工类（示例：网络工程）

**拓扑图检查**
- 是否有图例、图注。
- 设备图标与图例是否对应。
- 层次划分是否标注（核心层/汇聚层/接入层）。
- 链路类型是否标注（10G/1G、冗余/负载分担）。

**设备与协议检查**
- 设备型号是否真实存在（华为 S 系列、Cisco Catalyst 系列等）。
- 协议描述是否准确（如 OSPF 是链路状态协议，不是距离矢量）。
- 同一份报告中设备体系是否统一（华为与 Cisco 混用需说明理由）。

**层次模型检查**
- 核心层描述是否强调高速转发、冗余、不做策略处理。
- 汇聚层是否强调策略控制、流量聚合。
- 接入层是否强调用户接入、端口安全。
- 三层功能边界是否有矛盾描述。

## 编程/实现类

**命令检查（重点）**
- `-l`（小写 L，链接库）与 `-I`（大写 i，头文件目录）是否混用。
- `-c`（编译不链接）与 `-C`（预处理保留注释）是否混用。
- `-o`（指定输出）使用是否正确。
- 命令解释与命令本身是否一致（如用 `-l` 却说是头文件目录）。

**代码检查**
- 函数声明与定义是否一致。
- 头文件包含关系是否正确。
- 变量类型与使用是否匹配。

**makefile 检查**
- 目标与依赖关系是否完整。
- 命令行是否以 Tab 开头。
- clean 规则是否清理了所有生成文件。
- 变量引用是否一致（如定义了 `CC` 却用 `gcc`）。

## 调研/通识/公选类

**内容检查**
- 概念定义是否准确。
- 数据引用是否有来源、是否标注时间节点。
- 是否按要求"自己写"（对比模板和网络原文，判断是否有大段复制）。

**术语统一**
- 同一概念是否全文统一（如"AI漫剧"与"AI漫画"不能混用）。
- 专有名词大小写是否规范。

**字数核验**
- 中文字符数（含中文标点）。
- 数字和英文按连续串计为一个单位。
- 不足扣分，超出提醒不扣分。

## 平台工具选择

审核需要读取 Word 格式信息时，按以下优先级选择工具：

1. 若平台有 Python 运行环境，使用 `scripts/parse_docx.py`。
2. 若平台自带文档解析工具（如 DSH 的 MCP 文档工具），调用并请求格式信息。
3. 若都不可用，降级为纯文本读取，在报告中注明"格式检查受限"。
