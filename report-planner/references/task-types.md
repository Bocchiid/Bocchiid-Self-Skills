# 八种任务形态

按**任务形态**而不是学科分类。混合任务取「主形态 + 辅形态」。下面每类给出：
识别信号、典型任务、步骤骨架、L1 证据、高分关键、常见坑。

> **绘图要求统一交给 writer。** 流程图、架构图、时序图、SWOT 图、示意图等报告插图，
> 不列入用户的 L1 证据/截图清单；用户只提供依据（报文顺序、拓扑截图、数据表、引用），
> 图由 `report-writer` 绘制。例外：设计草图/原型/手绘稿如果本身就是任务产物，
> 按"任务产物"处理，不是"截图"。

> 步骤骨架是起点，不是照抄模板。实际步骤以用户描述为准；指导书与用户描述冲突时，
> 按用户描述拆，并在「与指导书差异」里记录。

## 1. 操作验证型

**识别信号**：有设备/软件操作、配置命令、参数设置、状态验证；产出是"能运行/能连通/
能复现"的系统或现象。

**典型任务**：网络设备配置、服务器部署、化学/物理操作实验、软件安装与配置、
安全策略配置、虚拟化/容器操作。

**步骤骨架**：

1. **准备**：确认设备/软件/版本、权限、拓扑/连接、备份当前配置；记录基线状态。
2. **基线验证**：在不改配置的情况下验证初始状态（能否登录、能否连通、初始读数）。
3. **分步操作**：按依赖顺序配置；每完成一个逻辑单元就验证一次，不要全部配完再测。
4. **结果验证**：用独立方法验证（ping/traceroute/抓包/功能测试/复测），而不是只看配置页。
5. **异常处理**：记录失败现象、报错、回退方法；保留失败现场。
6. **收尾**：保存配置、导出日志/数据、恢复现场（如要求）、备份。

**L1 证据**：

- 环境与版本（设备型号、系统/软件版本、拓扑）
- 基线状态（操作前）
- 关键配置（含接口/参数/策略）
- 验证命令与输出（成功）
- 至少一次失败/异常及处理（如果发生过）
- 最终状态（保存后/重启后仍生效）

**高分关键**：参数完整、顺序正确、有独立验证、能解释"为什么这样配"、有回退/异常处理。

**常见坑**：只截配置页不验证；截图看不到设备名/接口/版本；配置没保存；失败现场没留；
把"命令敲完了"当成"实验成功"。

---

## 2. 编程实现型

**识别信号**：要写代码、编译/解释运行、测试、调试；产出是可运行程序或脚本。

**典型任务**：网络编程、算法实现、Web/后端开发、数据处理脚本、自动化任务。

**步骤骨架**：

1. **需求与接口**：输入/输出、协议/格式、边界条件、运行环境。
2. **设计**：模块划分、数据结构、关键流程；先写清"怎么判断做对了"。
3. **环境准备**：语言/库版本、依赖安装、编译命令、目录结构。
4. **编码**：先跑通最小可用版本，再补功能；关键逻辑加注释/日志。
5. **测试**：正常用例、边界用例、异常用例；记录输入、期望、实际。
6. **调试**：保留报错、定位过程、修复前后对比。
7. **对比/优化**（如要求）：不同算法/参数/实现的性能或效果对比。
8. **收尾**：整理代码、README/运行说明、测试数据、版本记录。

**L1 证据**：

- 目录结构与运行环境/版本
- 关键代码段（含文件名/函数名）
- 编译/运行命令与输出
- 测试用例与结果（至少正常 + 边界）
- 关键报错与修复（如果发生过）
- 最终可运行证明（完整输出/截图）

**高分关键**：可运行、可复现、边界与异常处理、代码与报告描述一致、有测试/对比数据。

**常见坑**：只贴代码不贴运行结果；代码与报告里的命令/参数不一致；没有边界测试；
截图看不到文件名/路径；把网上代码原样贴入且无法解释。

## 3. 测量实验型

**识别信号**：有测量装置、读数、原始数据、重复实验、误差分析；产出是数据与结论。

**典型任务**：物理/电子/化学实验、信号测量、性能测试、统计调查中的测量部分。

**步骤骨架**：

1. **原理与假设**：测什么、为什么这样测、预期关系。
2. **装置与样本**：设备型号、量程、精度、样本/材料、环境条件。
3. **校准/预实验**：零点校准、试测、确认量程与读数方式。
4. **正式测量**：按方案记录原始数据（含单位、有效数字、环境条件）。
5. **重复/对照**：重复测量、对照组、不同条件对比。
6. **数据处理**：公式、单位换算、有效数字、图表、异常值处理。
7. **误差分析**：系统误差/随机误差、来源、对结论的影响。
8. **收尾**：保存原始数据、标注版本、记录异常。

**L1 证据**：

- 装置/环境照片或配置
- 参数与量程设置
- 原始数据表（含单位、表头、时间）
- 计算过程/工具输出
- 图表（含坐标轴、单位、图例）
- 异常值/失败数据及处理说明
- 重复实验记录

**高分关键**：原始数据完整、单位与有效数字规范、有对照/重复、误差分析具体、图表可读。

**常见坑**：只给处理后的数据，没有原始记录；单位/有效数字混乱；异常值直接删掉不说明；
图表没有坐标轴单位；把"数据好看"当成"结论正确"。

## 4. 调查调研型

**识别信号**：有问卷、访谈、样本、平台数据、市场/用户/现状分析；产出是描述、解释、
趋势判断或建议。

**典型任务**：电子商务现状调查、消费者行为调研、社会调查、竞品分析、用户研究、
行业报告解读。

**步骤骨架**：

1. **问题与假设**：要回答什么、为什么值得调查、预期结论方向。
2. **对象与样本**：调查谁、样本量、抽样方式、代表性限制。
3. **工具设计**：问卷题目/访谈提纲/观察表；避免诱导性问题。
4. **采集**：发布/预约/访谈/抓取；记录时间、渠道、回收量。
5. **清洗**：无效问卷、缺失值、异常值、匿名化。
6. **分析**：描述统计、交叉分析、分类归纳、引用原话；图表呈现。
7. **结论与建议**：回答研究问题、说明限制、给出可执行建议。
8. **收尾**：保存原始数据、来源链接与日期、知情同意/匿名记录。

**L1 证据**：

- 调查问题/问卷题目/访谈提纲
- 样本量与样本分布（渠道、时间、人群）
- 平台/网页数据截图（含 URL、日期）
- 原始数据表或匿名转写
- 分析图表
- 来源清单（报告名、机构、年份、链接）
- 隐私/知情同意说明（如涉及人）

**高分关键**：样本与问题匹配、数据来源可信、有数据支撑的判断、区分事实与观点、
引用规范、说明局限。

**常见坑**：样本量很小却下普遍结论；问卷题目诱导；只贴截图不分析；数据来源无日期；
把网上观点当数据；访谈内容未经同意公开。

## 5. 设计策划型

**识别信号**：要产出方案、原型、计划书、预算、流程设计；产出是"打算怎么做"而不是
"已经跑出结果"。

**典型任务**：电子商务网站策划、商业计划书、创新创业项目、活动策划、系统设计、
课程设计中的方案部分。

**步骤骨架**：

1. **背景与目标**：解决什么问题、面向谁、目标可衡量。
2. **需求/用户**：用户画像、场景、痛点、需求优先级。
3. **方案构思**：至少 2 个方案；每个方案的核心思路。
4. **方案对比**：技术/成本/时间/风险/合规等维度；给出选择理由。
5. **详细设计**：功能/结构/流程/原型/界面/技术栈。
6. **可行性**：市场、技术、经济、运营、法律合规。
7. **实施计划**：任务分解、进度、预算、分工、风险应对。
8. **收尾**：方案版本、假设清单、待验证事项。

**L1 证据**：

- 需求清单/用户画像/调研数据
- 方案草图/原型（任务产物；报告里的流程图/架构图由 writer 绘制）
- 方案对比表（≥2 方案，维度≥5）
- 预算/进度/分工表
- 风险与应对表
- 引用/数据来源（市场数据、法规、竞品）

**高分关键**：目标可衡量、方案≥2 且对比有依据、可行性分析具体、逻辑闭环（问题→方案→
验证→计划）、有风险意识。

**常见坑**：只有一个方案；对比只说"A 好 B 不好"；目标空泛（"做一个好用的网站"）；
预算/进度拍脑袋；方案与需求脱节；把设想写成已实现。

## 6. 案例文献型

**识别信号**：要读文献/案例、提炼观点、分析论证；产出是分析、评论、综述或研究性报告。

**典型任务**：管理案例分析、文学/文化课程读书报告、历史研究、政策分析、文献综述、
思政/通识课程论文。

**步骤骨架**：

1. **问题界定**：研究问题、范围、为什么重要。
2. **检索策略**：关键词、数据库、筛选标准、时间范围。
3. **材料筛选**：一手/二手、权威性、相关性；记录出处。
4. **阅读笔记**：核心观点、证据、方法、局限；用自己的话概括。
5. **分析框架**：比较维度、理论视角、因果/机制。
6. **论证**：观点 + 证据 + 反例/限制；避免堆砌摘要。
7. **结论**：回答研究问题、指出局限、提出进一步问题。
8. **收尾**：参考文献格式、引用核对、查重。

**L1 证据**：

- 检索式与检索结果（数据库、关键词、数量）
- 文献/案例清单（作者、年份、来源）
- 关键原文摘录/页码
- 分析框架图/对比表
- 引用与正文对应关系

**高分关键**：来源可靠、观点与证据一一对应、有比较和批判、引用规范、不是摘要拼接。

**常见坑**：只罗列文献不分析；引用无页码/来源；把网络百科当权威；观点与材料脱节；
参考文献格式混乱；大段直接引用不加引号。

## 7. 项目综合型

**识别信号**：有团队、多阶段、里程碑、交付物；产出是完整项目或课程设计。

**典型任务**：课程设计、毕业设计、小组项目、创新实践项目、竞赛作品。

**步骤骨架**：

1. **需求与目标**：问题、用户、范围、验收标准。
2. **调研与选型**：文献/竞品/技术方案对比。
3. **方案与计划**：架构/路线、任务分解（WBS）、进度、分工、风险。
4. **实施**：按里程碑推进；版本管理；会议/决策记录。
5. **测试/验收**：测试用例、验收标准、问题清单、修复记录。
6. **交付**：代码/文档/演示/部署说明。
7. **总结**：个人贡献、技术比较、不足与改进、未来展望。

**L1 证据**：

- 需求/范围/验收标准
- 分工表与个人贡献记录
- 里程碑/进度记录（含延期与调整）
- 会议纪要/决策记录
- 版本/提交记录
- 测试记录与缺陷修复
- 演示/部署截图
- 个人工作证明（负责模块、产出）

**高分关键**：个人贡献可验证、过程可追溯、方案有对比、风险有应对、总结有反思。

**常见坑**：分工写成"大家都参与"；个人贡献无法证明；只写结果不写过程；进度表是事后编的；
小组报告雷同；把团队成果说成个人成果。

## 8. 体验观察型

**识别信号**：参观、访谈、观展、志愿服务、实地体验、田野观察；产出是记录、观察分析、
反思报告。

**典型任务**：企业参观、博物馆/展会记录、社区调研、田野调查、志愿服务、访谈类作业。

**步骤骨架**：

1. **准备**：目的、对象、时间地点、预约/许可、观察提纲/访谈提纲。
2. **现场记录**：时间、地点、人物（匿名）、环境、关键事件、原话、照片（如允许）。
3. **即时整理**：当天补齐笔记，标注不确定/待核实。
4. **补充材料**：公开资料、背景信息、后续追问。
5. **分析**：分类、对比、主题归纳、与课程概念对应。
6. **反思**：自己的观察偏差、限制、收获、改进。
7. **收尾**：匿名化、授权确认、来源标注。

**L1 证据**：

- 时间/地点/对象信息（可公开部分）
- 观察笔记/访谈转写（匿名）
- 现场照片（如允许，含时间地点）
- 预约/签到/许可记录（如适用）
- 背景资料与来源
- 知情同意/匿名处理说明

**高分关键**：记录具体（细节、原话、场景）、分析与课程概念结合、有反思、伦理规范。

**常见坑**：只写感受不写事实；记录笼统（"收获很大"）；照片涉及他人未同意；
把网上资料当成现场观察；时间和地点对不上。

## 混合任务怎么处理

| 组合 | 处理 |
| --- | --- |
| 操作 + 测量 | 以操作为主线，测量数据作为验证证据；步骤表合并，证据分两套 |
| 编程 + 项目 | 以项目阶段为主线，编程步骤嵌入实施阶段；个人贡献单独列 |
| 调研 + 设计 | 调研作为设计的前置证据；报告章节按"现状→问题→方案→可行性"组织 |
| 文献 + 案例 | 检索/阅读作为过程，案例分析作为产出；证据同时要文献清单和案例材料 |

混合任务在执行卡/详细版开头写清主/辅形态，步骤表用一列标"形态"，避免两套流程打架。
