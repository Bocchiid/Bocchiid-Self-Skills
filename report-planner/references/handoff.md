# 交接给 report-writer / report-reviewer

执行卡/详细版不是最终报告，而是下游 skill 的输入。交接的目标是让 writer 不用重新猜任务，
也让 reviewer 能对照同一套要求审核。

- **执行卡 = 即开即用版**：现场照着做；
- **实验指导书 = 完整版**：用于用户确认目的/差异/证据细节和报告结构。

**两份都交接**（`实验执行卡.md` + `实验指导书.md` + 证据目录）。只交接执行卡，
writer 会缺少目的、差异、报告映射和变更记录。

**交接给 writer 的硬条件**：所有阶段的 L1 证据通过、实验步骤完成或明确跳过、
`截图验收.md` 存在且没有“不通过/待补拍”。不满足时先补拍或改执行卡，
**不要直接进入 writer**。

## 1. 交接什么

| 内容 | 在执行卡/详细版里的位置 | 为什么 writer 需要 |
| --- | --- | --- |
| 实际方案与指导书差异 | 详细版 §1.2、§1.3 | 避免按过时指导书写错 |
| 实验目的逐条清单 | 详细版 §1.1 | 确保报告覆盖目的 |
| 硬要求与评分表拆解 | 详细版 §2.2、§2.3 | 不漏项、知道写到什么程度 |
| 报告章节映射 | 执行卡 §4 / 详细版 §7 | 直接得到大纲和每节要点 |
| 证据清单与文件名 | 执行卡 §1 / 详细版 §6 | 知道每张图/表插在哪、题注叫什么 |
| 目的-步骤-证据矩阵 | 详细版 §4 | 保证每一节有材料支撑 |
| 变更记录与待确认问题 | 详细版 §9、§12、§2.4 | 避免把未确认信息写死 |
| 现场步骤与失败速查 | 执行卡 §2、§5 | writer 了解实际执行过程与已知问题 |
| 截图验收记录 | `截图验收.md` / 执行卡末尾 | 知道哪些证据已通过、哪些待补 |
| writer 需要绘制的图/表 | 执行卡 §4 / 详细版 §7.1 | 明确哪些图由 writer 画、依据哪些证据 |

## 2. 材料包怎么组织

建议在任务目录下形成这样的结构（文件名可按课程惯例调整）：

```text
<任务目录>/
├── 实验执行卡.md          # 即开即用版
├── 实验指导书.md          # 完整版（必做；旧名 实验规划书.md）
├── 截图验收.md            # 分阶段截图验收记录
├── 材料/
│   ├── 指导书.pdf
│   ├── 报告模板.docx
│   └── 评分表.png
├── 证据/
│   ├── 截图/
│   │   ├── S1_环境版本_20261019.png
│   │   ├── S3_配置_20261019.png
│   │   └── S5_验证成功_20261019.png
│   ├── 数据/
│   │   ├── raw.csv
│   │   └── processed.xlsx
│   └── 记录/
│       ├── 访谈转写_匿名.md
│       └── 日志.txt
└── 报告/
    └── <按模板命名的报告>.docx
```

规则：

- 证据文件名与执行卡 §1 / 详细版 §6 的 ID/文件名一致；
- 原始文件与标注文件分开；
- 不把截图直接粘进聊天就不管，保留磁盘原文件；
- 报告里用的图/表，在执行卡或详细版里能找到对应证据 ID。

## 3. 交接说明模板

在执行卡末尾或聊天里给 writer 一段话：

```markdown
## 交接说明

- 执行卡版本：v1.0（已确认）
- 实际方案：按用户描述，与指导书差异见详细版 §1.3
- 报告模板：<文件名>；交付格式：<.doc/.docx>
- 章节映射：见执行卡 §4；每节要回答的问题已列出
- 证据：见执行卡 §1；L1 证据已齐/还缺 <清单>
- 报告插图：见执行卡 §4 / 详细版 §7.1；由 writer 绘制，用户只提供依据
- 需要 writer 注意：
  - 不要改动封面、评分表、模板预填内容；
  - 图/表按执行卡 §1 / 详细版 §6 的证据 ID 放置，题注名称建议为 ...；
  - 用户未确认的信息不要写成定论。
- 尚未补齐：<材料/数据/截图>
```

## 4. 与 report-writer 的口径对齐

规划时就要遵守 writer 的规则，避免交接后返工：

| 规则 | 对规划的影响 |
| --- | --- |
| 用户描述优先 | 规划按实际方案写；差异单列，不强行对齐指导书 |
| 只写需编写区域 | 不规划封面、评分表、教师评语、模板预填内容 |
| 图/表/参考文献是条件项 | 没有要求就不硬加；有要求才进证据清单 |
| 模板优先、只插入不覆盖 | 报告映射按模板章节走，不自创结构 |
| 保护区逐字节不动 | 规划里提醒用户不要改模板；证据不要求改模板 |
| 交付格式跟模板走 | 在 §1.4 写清 `.doc` / `.docx` |

## 5. 与 report-reviewer 的衔接

如果用户写完报告要审核，把以下内容一起给 reviewer：

- 执行卡（§1 截图、§2 步骤、§4 映射、§5 失败速查）**和实验指导书**
  （§1.3 差异、§2.4 待确认）；
- 实际方案差异说明；
- 证据文件与报告；
- 尚未解决的问题清单。

reviewer 会用同一套"用户描述优先、只审需编写区域、条件项不扣分"的口径判断，
避免把规划里已说明的合理差异判成错误。

## 6. 不要交接什么

- 不要交接编造的数据、截图、访谈或文献；
- 不要把"规划建议"写成"老师要求"；
- 不要把未确认的假设当成事实；
- 不要让 writer 替用户改模板保护区；
- 不要把成品报告当作内容来源（只能参考格式）。
