# 材料盘点、追问与环境检查

写报告之前先把这三件事做完，能省掉大量返工。

## 一、材料清单

### 必需

| 材料 | 为什么必需 | 缺失时的话术 |
| --- | --- | --- |
| **实验指导书 / 任务书** | 报告的实质内容全部来自它——做什么、分几步、要观察什么现象 | "方便提供一下实验指导书或任务书吗？报告要写哪些步骤、分析哪些现象，都以它为准。" |
| **报告模板**（文件名通常含"模板"字样） | 格式、框、评分表都在里面，没有它就只能猜格式 | "有实验报告模板吗？没有的话，我按同类报告的通行格式来写，但格式打分可能会吃亏。" |

用户明确回答"没有"时，**就用现有材料继续做**，不要卡住不干活；但要在交付时说明依据有限，以及哪些地方是推断的。

### 期望有，没有就问

| 材料 | 用途 | 话术 |
| --- | --- | --- |
| **图片 / 截图** | 实验结果的主要证据 | "实验过程的截图有吗？放在哪个目录？" |
| **数据 / 表格** | 同上 | "有需要整理成表的原始数据吗？" |
| **待填写的报告文件** | 多数情况就是模板的一份副本 | "是直接在模板副本上写，还是我新建一份？" |
| **同课程的成品报告** | 仅用于**格式迁移**与参照 | "有之前写完的同课程报告吗？我想参照它的格式（不会抄内容）。" |

### 细节字段

姓名、学号、实验日期、实验地点、同组成员、课程名、指导教师——缺哪个问哪个。

这些字段写在封面，**错了比正文写错还显眼**，而且用户往往觉得"这不是明摆着的吗"所以没提。宁可多问一句。

日期默认取**今天**，但要让用户确认；学号姓名从文件名里可能已经有了（很多作业文件就叫 `<学号>-<姓名>-实验N.doc`），先看一眼再问，别问已经给了的信息。

## 二、确认怎么"交付"

用户很可能已经有一份以学号姓名命名的空报告（通常就是模板的副本）。先确认：

> 我直接在 `<学号>-<姓名>-实验5.doc` 上写，还是另存一份？

**直接新建文件的情况要格外小心**——没有模板兜底，格式全靠自己定，交付前更要把字号、标题层级、页边距梳理一遍。

## 三、环境检查（写之前做一次）

```bash
python scripts/docx_env.py --check
```

- `ready: true` → 静默继续。
- `python_docx: null` → 需要 `pip install python-docx`。说明装了能做什么、不装会失去什么，问一次是否代装。装不上的镜像源见 README。
- `word_com: null/false` → 处理老式 `.doc`、更新域、导出 PDF 会受影响。改用 `scripts/word_com.ps1`（走 PowerShell 调 COM，不依赖 pywin32）。

询问只在会话开始做一次，用户选完就不再重复。

## 四、目标文件是否被 Word 占用

**在动手之前查，不要等写失败了才报错。**

写文件前先试着以独占方式打开目标文件；失败就说明它在 Word 里开着：

```powershell
try { $fs = [System.IO.File]::Open($path, 'Open', 'ReadWrite', 'None'); $fs.Close() }
catch { Write-Host "被占用" }
```

此时直接告诉用户：

> 目标文件现在在 Word 里开着，写不进去。请先关掉它，我再继续。

（`word_com.ps1` 内置了这个检测。）同理，交付新文件时如果同名文件开着，也要提醒。

## 五、动手前的确认清单

信息齐了之后，开工之前跟用户对齐一次：

1. **大纲**——准备分几节、标题层级怎么排。
2. **编号起点**——正文从哪一节的哪个编号开始（模板常常已经写好"四、""五、"，你只需要填内容）。
3. **图/表是否参与编号**——模板里原有的图/表要不要接着编号（**默认不参与**，见 `writing.md`）。
4. **交付格式**——**默认跟模板一致**：模板是 `.doc` 就交 `.doc`，是 `.docx` 就交 `.docx`。只有用户明确要求换格式时才例外。
5. **中间产物放哪**——默认写在报告所在目录下（见 `docx-cookbook.md` 的工作目录约定）。

一次问清比来回返工省事得多。
