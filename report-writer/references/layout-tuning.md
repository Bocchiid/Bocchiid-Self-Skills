# 页面利用率：度量与收敛

## 要解决的问题

Word 不能把一张图或一个表格拆到两页。一个大块塞不进页尾剩下的空间时，整块会被挪到下一页，**上一页就留下一整块空白**——典型症状是某一页只用了 50%~70%，后面全是空白。

目标：在**需要编写**的页面里，除了正文收尾的最后一页，每页都排得比较满。

## 统计范围：只算我们需要编写的页

**利用率只统计我们编写的页面**：实验步骤、实验结果分析、用例分析等。
下面这些页不参与计算——它们不是我们排版的产物，页尾空着是模板本来的样子：

- 封面页
- 评分点 / 评分表 / 教师评语页
- 模板自带的实验说明、格式说明页
- 空白页

`page_fill.py` 默认会自动跳过封面、评分/评价页和空白页；模板说明页这类无法可靠
自动识别的，用 `--list` 看页码后 `--exclude` 显式排除，或者用 `--pages` 直接圈定
自己写的那几页。

## 度量

```bash
python scripts/word_com.ps1 -Action to-pdf -In out.docx -Out preview.pdf   # 先出 PDF

python scripts/page_fill.py preview.pdf --list          # 先看每页分类与首行
python scripts/page_fill.py preview.pdf                 # 自动排除封面/评分/空白页
python scripts/page_fill.py preview.pdf --exclude 2,3   # 再排除模板说明页
python scripts/page_fill.py preview.pdf --pages 4-9      # 或只统计自己写的页
```

输出每页的利用率与底部空白（pt），并列出被排除的页及原因。判读：

- **参与统计的最后一页天然不满**——正文到此结束。这不是问题。
- **中途某页低于 ~85%** 才是要处理的。
- **不要统计封面/评分页/说明页**，也不要把它们的空白算进"正文段底部空白合计"。
- 先量一版基线，再动手，否则分不清改动有没有效果。

## 定位阻塞块

不要看见空洞就缩图片。先搞清楚**是哪一块被挪到了下一页**：

1. 看空洞那页底部还剩多少（`gap_pt`）；
2. 看下一页开头是哪一块（图？表？）；
3. 算它要多大才塞得进去。

```bash
# 打印指定页的纵向排布：每块的 y 范围、类型、高度
# --json 里 selected_pages / skipped_pages 就是本次统计的范围，先确认口径
python scripts/page_fill.py preview.pdf --json      # 先用它找出页码
python -c "
import pymupdf, io
d = pymupdf.open('preview.pdf'); pg = d[11]          # 第 12 页
for b in pg.get_text('dict')['blocks']:
    print(round(b['bbox'][1],1), round(b['bbox'][3],1), b.get('type'))
for i in pg.get_image_info():
    r = i['bbox']; print(round(r[1],1), round(r[3],1), 'IMG %.0fx%.0f' % (r[2]-r[0], r[3]-r[1]))
"
```

（输出含中文时重定向到 UTF-8 文件再读，别直接怼控制台——cp936 会抛 `UnicodeEncodeError`。）

块的纵向尺寸：

```
图片块高 = 显示宽度 × 宽高比 + 题注高(≈14 pt)
表格块高 = 表题(≈11) + 各行高之和
```

要让它塞进 `gap` 里，图片宽度得满足 `宽 ≤ (gap - 14) / 宽高比`。

## 处理优先级

### 1. 卡住的是表格 → 让表格跨页续排

**这是最有效的一招。** 讨论/对比类的表格动辄 300~400 pt 高，永远塞不进页尾剩的一两百 pt，而它又不是图片，没法"缩"。

```python
K.wrapped_table(caps, 'tab03', '控制器与交换机建立连接阶段的报文',
                rows, widths, split=True)
```

`split=True` 时去掉外层包裹表格的 `cantSplit`，整表可以在页与页之间断开；每个单元格内部的 `cantSplit` 保留，所以**单行不会被拦腰截断**。

实测（一份 17 页、含 24 张插图的实验报告）：

| 配置 | 页数 | 中途空白合计 | 最差页利用率 |
| --- | --- | --- | --- |
| 表格不跨页 | 18 | 906 pt | 66% |
| 表格跨页 | **17** | **315 pt** | **81%** |

**代价**：Word **不会**为嵌套在单元格里的表格重复表头行（`w:tblHeader` 会被静默忽略）。表从第二页续上时没有表头，只能靠边框延续辨认。可接受，但要跟用户说明。

### 2. 卡住的是图片 → 按需缩，且只缩必须缩的那张

先算所需宽度。若 `所需宽度 ≥ 默认宽度 × 85%`，缩下去不影响阅读，就缩到刚好放下：

```python
IMG_W_BY_NAME = {'10 openflow_v1 packet.png': 395.0}   # 只缩这一张
```

若 `所需宽度 < 85%`，说明这张图缩下去就糊了——**别硬缩**，改去压缩同页其它块，或者接受这一页。

### 3. 同页还有别的图 → 一起微调

页尾剩 `gap`，要放的块高 `H`，同页还有一张高 `h` 的图可以缩到 `h'`：满足 `gap + (h - h') ≥ H` 即可，两边各让一点，比把一张压到糊更划算。

## ⚠️ 不要全文统一缩放

这是最容易走错的一步。把每张图都改小**并不能**填满页面。

原因：**总空白 ≈ 页数 × 每页高度 − 内容总高度。**

内容缩了，页数不变的话，空白反而**更多**；只有缩到正好少掉一整页，空白才会减少。而且图变小之后，原本"两张刚好占满一页"的组合会变成"两张加半页空白"，反而更难看。

实测（同一份报告，20 多组尺寸组合逐一用 Word 真实排版后测量）：

| 统一宽度 | 中途空白合计 | 页数 |
| --- | --- | --- |
| 390 pt | 1060 pt | 18 |
| **420 pt（默认）** | **955 pt** | **18** |
| 430 pt | 1474 pt | **19** |
| 440 pt | 2070 pt | **20** |

统一 420 pt 已是这批组合里最好的；放大反而更多页。

**结论：按图逐个调，不要全局统一。** 真正有效的三件事是：

1. 让大表格跨页（见上）；
2. 只调**被挪到下一页**的那张图；
3. 流程图之类的自绘图，重画时**压紧行距**——字号不变、只收掉行间空白，图能矮 20% 以上，且完全不影响阅读。

## 收敛流程

```bash
# 1. 量基线（先 --list 确定页码范围，之后每轮都用同一口径）
python scripts/page_fill.py preview.pdf --exclude 2,3
# 2. 定位阻塞块，按上面的优先级处理，改 build.py
# 3. 重建 → 出 PDF → 再量
python scripts/page_fill.py preview2.pdf --exclude 2,3
# 4. 重复，直到需编写页里没有低于 85% 的中途页，或剩下的洞确实无法消除
```

**每轮保持同一统计口径**：`--exclude`/`--pages` 前后一致，否则"空白减少了"可能
只是把模板页排除了，不是真的改好了。

每轮改动都是一次真实的 Word 排版，单轮约 40 秒，一般 2~3 轮收敛。

要批量比较多种尺寸组合时，把宽度做成环境变量，循环构建 → 用 `word_com.ps1` 批量转 PDF → `page_fill.py --json` 打分，比手工试快得多。

## 剩下消不掉的空洞怎么办

有些空洞是真的消不掉——比如某一页底部要放一张 A4 宽度的流程图，它怎么都得占大半页。这时候：

- 如实告诉用户**为什么**消不掉（"这张图缩到能放下的宽度只剩 6 pt 字，看不清"）；
- 给出取舍选项（让表格跨页 / 裁掉截图里与结论无关的部分 / 接受现状），别自己默默决定；
- **不要**为了塞满而把图缩到看不清——那是本末倒置。
