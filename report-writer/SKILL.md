# 报告撰写

从材料到成稿：**盘点材料 → 解析模板 → 规划结构 → 插入内容 → 图表题注与交叉引用 → 调页面利用率 → 更新域交付**。

**三条底线**（任何时候都不能破）：

1. **模板优先，只插入不覆盖** —— 框、页眉页脚、封面、评分表、样式定义一律保持原样。
2. **格式只对齐"需编写区域"** —— 模板里不需要你写的部分原样跳过，不要"顺手统一"。
3. **内容基于指导书、模板、用户给的图片表格与检索结果，不抄成品报告。**

**两条工作约定**：产出格式与模板一致（`.doc` → `.doc`，`.docx` → `.docx`）；
中间产物写在报告所在目录，不要散到系统临时目录。

## 需求从哪来：按优先级定

| 优先级 | 来源 |
| --- | --- |
| **1（最高）** | **用户的要求** —— 说了算，哪怕与模板、指导书不一致 |
| 2 | **实验指导书 / 任务书** —— 任务分解、要分析什么 |
| 3 | **模板里明写的要求** |
| 4（最低） | 默认 —— 只做最小必要的事，**不自作主张加东西** |

⚠️ **图、表、参考文献都不是默认项。** 指导书没要求、模板没要求、用户也没提，
就别硬加——一份纯操作记录的报告可能一张图都没有，一份没引用他人工作的报告
也不需要参考文献表。

反过来，**模板明写了就变成硬要求，必须做**：「正文字数不少于 2000 字」
「参考文献不少于 3 篇」「从××、××、××角度总结」「要求使用时序图描述」
「定稿时删除红字部分和以下格式模板内容」。

## 第零步：材料盘点与环境探测

```bash
find . -type f -not -path "*/.git*" -printf "%10s  %p\n" | sort -k2
python scripts/docx_env.py --check
```

（清单只看**文件名和大小**，别读二进制——成品报告动辄十几 MB。）

要找三样：**模板**、**指导书/题目**、**同课程成品报告**（仅用于参照格式，
不做内容来源）。别只按"模板"两个字找——命名惯例因课而异，检索方法与追问话术见
`references/course-conventions.md` 和 `references/intake.md`。

姓名、学号、日期、同组成员这类字段缺了就直接问——写错比正文写错还显眼。

**写入前先确认目标文件没在 Word 里开着**，开着就提前告诉用户，别等写失败才报错。

## 第一步：解析模板

这一步的目标不是"找到框"，而是**在不破坏模板的前提下确定往哪写**。

"留给你填写的区域"有四种形态：

| 形态 | 样子 |
| --- | --- |
| ① 单列长表（带/不带边框） | 内容堆在一列，某几行留空 |
| ② 多列表单 | `报告名称｜____`、`问题介绍｜____` |
| ③ 正文区与评分表拼在一张表 | 前半是填写栏，后半是打分表 |
| ④ 纯段落结构 | 没有表格，靠"主要内容："这类锚点定位 |

**只有 ① 能自动识别。** 其余三种任何启发式都会在某一门上猜错，而猜错的代价是
**静默地把正文写进评分表**——比找不到更糟。所以不猜，固定走四步：

**a) 勘察** —— `python scripts/docx_env.py --plan 模板.docx`

输出形态判定、**可直接复制的 `Target` 候选**、要避开的评分区、已识别的封面字段，
以及下一步代码。候选只是**建议**。要看更细的逐行事实用 `K.survey(d)`。

**b) 显式指定** —— 不要猜，直接指名：

```python
K.Target.cell(table=1, row=3)   # 表格式（形态 ①②③）
K.Target.after('主要内容：')     # 段落式（形态 ④）
K.Target.at_end()               # 追加到文末
```

**c) 写入前检查** —— **这道闸是强制自动的**：`check_target()` 在第一次 `put()`
时自动执行，拦到"疑似评分行"或"目标格已有内容"就抛错，**而且文档一个字节都没动**
（清空目标格推迟到检查通过之后）。确实判断是误报时用 `cur.force('理由')` 放行——
不给理由会报错。

**d) 写入后比对** —— `cur.finish()` 比对表格结构指纹。正常**只报目标格的字数变化**；
出现别的条目就是模板被动了（行数变了、别的格子变了），回滚重来。
这一步不依赖任何猜测，是最后一道闸。

**没有模板时**按优先级降级，别自己拍板：用户有模板 → 用模板；有**同课程**成品报告
→ 从它迁移格式；两样都没有或只有别课程的 → **询问并协商**，不要默认。

⚠️ 模板正文若放的是「正文 xxx字体 xxx字号」这类**格式说明**，严格照它做——
比任何推测都权威。

> 每一步的细节、`survey()` 输出样例、报错信息、**格式提取方法**，
> 见 `references/template-analysis.md`。

## 第二步：规划结构

**先把要求拆成两份清单**，写完逐条打勾——漏一项就是漏一项分。

**① 评分表**（模板里几乎都有，"评价内容/评价依据/赋分区间"）：把每一行拆成
"可核对的写作要点 + 对应报告哪一节"。

> 例："分析与解释……过程与机制" → 结果分析各节 → 要**逐项/逐字段解读**，不能只贴截图。

没有评分表就用指导书的"任务分解表"或"要求"代替，效果一样。

**② 明写的硬要求**（散落在正文各处，最容易漏）：字数下限、参考文献篇数、
必须覆盖的角度、必须有的图、要求删除的说明文字、要求附的程序清单 / 数据记录。

评分表决定"写到什么程度"，硬要求决定"必须有什么"。

**再定大纲**：小标题层级用完一层再用下一层 ——
`1.` → `(1)` → `①②③` → `1.1`。层级格式随模板（模板做成加粗黑体就照做）。
定完给用户过一眼，层级错了返工很贵。

## 第三步：写入内容

**一律"插入"，不要"覆盖"。**

```python
import sys; sys.path.insert(0, r'<skill>/scripts')
from docx import Document
import docx_kit as K

d = Document('work.docx')                              # 由 word_com.ps1 从 .doc 转来
cur = K.Cursor(d, K.Target.cell(1, 3), keep_paras=1)    # 目标来自第一步；检查自动跑

caps = K.Captions()
caps.declare('fig_topo', '图')                          # 先按最终出现顺序登记全部编号

cur.put(K.heading(1, '1. 网络拓扑搭建'))
cur.put(K.body(caps, '拓扑见<<fig_topo>>。'))            # <<key>> 渲染成交叉引用
cur.put_image('pics/topo.png', 400)
cur.put(K.caption(caps, 'fig_topo', '实验网络拓扑'))

assert not cur.finish()                                 # 非空 = 模板被动了，回滚
d.save('out.docx')
```

内容来源：**指导书 + 模板 + 用户给的图片/数据 + 联网检索**。用户给了成品报告，
它只用于对齐格式，**文字必须自己写**——学术诚信，没有例外。

结果分析要有信息量：对截图做**字段级解读**（读数、算差值、指出异常），
不要复述"如图所示能看到……"。写得好不好的判据、代码怎么贴（有截图用截图，
否则用等宽灰底文本块）见 `references/writing.md`。

## 第四步：图表（这份报告有图表时才做）

没有就整节跳过。有的话：

- 题注固定 **`图 3 名称` / `表 2 名称`**——前缀、空格、编号、空格、名称，
  无论中英文打头**空格数都一致**。编号用 `SEQ` 域（插删后自动连续）+ 书签，
  正文用 `REF` 域引用。
- **模板里原有的图/表不动**：不加题注、不改编号、不参与交叉引用。
- **图注在图下方，表注在表上方**；**图和题注必须在同一页**——插图段落自带
  `keepNext`，表格用 `wrapped_table` 包一层无边框 1×1 表格，让 Word 整块挪动。
- ⚠️ 域没刷新时读者看到的是缓存值，`caption()` 里的缓存编号必须填对
  （`docx_kit` 已按登记的编号填好），交付前再用 `word_com.ps1` 刷两遍兜底。

`Captions` 用**两遍法**：先 `declare` 全部编号再渲染——这样"如图 4 所示"即使写在
图 4 之前也不会串号。

## 第五步：文献引用（引用了文献时才做）

没引用就整节跳过。**不要硬凑**一份和正文对不上的参考文献表，那比没有更显眼。

- 模板自带著录规范就**严格照它抄**；没写就用 **GB/T 7714 顺序编码制**。
- **正文里的引用序号必须是右上角标**（`<<cite:1>>`、`<<cite:2-4>>`），
  不是普通方括号——这点最容易漏。
- 文末列表**按正文首次引用顺序编号**，每条带类型标识 `[J]` `[M]` `[Z]`…
- 正文序号与文末列表**必须一一对应**：列了不引、引了不列都是硬伤。

完整著录格式（各类型、英文文献细则、常见错误）见 `references/citations.md`。

## 第六步：调页面利用率

主要针对**有大量截图 / 大表格**的报告——空白是被"塞不进页尾的大块"撑出来的。
纯文字报告跑一遍确认没问题就跳过。

```bash
python scripts/page_fill.py out.pdf      # 列出利用率低于 85% 的页
```

发现空洞**不要想当然地缩放图片**。先定位是哪一块被顶到了下一页
（量出本页剩余空间 → 看下一页开头是什么 → 算它要多大才塞得下），再按优先级处理：

1. **卡住的是表格** → 允许跨页续排（`split=True`）。**最有效的一招**：表格常有
   300~400 pt 高，永远塞不进页尾剩的 200 pt，而缩图救不了它。
2. **卡住的是图片** → 缩到刚好能放下；但若所需宽度 < 默认宽度的 85%，
   说明缩下去就看不清了，改去压缩同页其它块，或接受这一页。

⚠️ **不要全文统一缩放。** 图片整体缩小**不会**填满页面——总空白 ≈ 页数×页高 − 内容总高，
缩小只是把空洞挪个位置，除非正好少掉一整页（实测反而更容易多出几页）。
**按图逐个调**才有效。详见 `references/layout-tuning.md`。

## 第七步：交付与自检

**产出格式跟模板走**：`.doc` → 交 `.doc`，`.docx` → 交 `.docx`。别因为中途用
python-docx 编辑就把 `.docx` 当成交付物——格式和模板不一致，老师那边很可能打不开。

```bash
powershell -File scripts/word_com.ps1 -Action to-doc -In out.docx -Out 报告.doc
powershell -File scripts/word_com.ps1 -Action to-pdf -In out.docx -Out preview.pdf
```

**中间产物写在报告所在目录**（工作副本、构建脚本、压缩后的图片、预览 PDF），
别散到系统临时目录。只有遇到绕不过去的权限问题才退到临时目录，并说明放在哪。

交付前自查：

- [ ] 框还在；页眉页脚/封面/评分表没被动过；只有"需编写区域"被填，模板原有内容一字未改
- [ ] **评分表逐项核过 ＋ 硬要求逐条打勾，都没有漏**
- [ ] 小标题层级符合 `1.` → `(1)` → `①②③` → `1.1`，且与模板风格一致
- [ ] 模板要求删除的说明文字，删干净了
- [ ] 没有与受众不相称的操作流水账
- [ ] `page_fill.py` 无低于 85% 的中途页；文件体积合理
- [ ] **条件项（有才查）**：图表有题注且被正文引用、图与题注同页；
      文献是上标且与文末一一对应；代码用了等宽灰底文本块

最后**把成稿导出 PDF 翻一遍**——排版问题在 PDF 里最直观，比盯着 XML 猜快得多。

交付说明里可以建议一句"用 `report-reviewer` 再自审一遍"（**不自动跑**，由用户决定）。

## 边界

**做**：按模板产出 Word 报告；插入段落、图片、表格；题注与交叉引用；版面紧凑化。

**不做**：替用户编造实验数据；把成品报告改头换面当成新报告；
没有模板也没有参照时凭空发明格式（应当先问）。
