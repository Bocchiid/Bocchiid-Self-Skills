# 解析模板：框、可编写区域、格式

## 一、先搞清楚"框"是什么形态

模板一旦被写坏——框被撑破、评分表被塞进正文、页眉页脚丢失——整份报告就废了。
所以这一步的目标不是"找到框"，而是**在不破坏模板的前提下确定往哪写**。

### 为什么不能靠自动识别

"留给你填写的区域"至少有四种形态，实测都遇到过：

| 形态 | 表现 | 例子 |
| --- | --- | --- |
| **① 单列长表** | 内容自上而下堆在一列里，某几行留空 | 表格只有 1 列，7~12 行 |
| **② 多列表单** | 每行是一个栏目：`标签｜填写区` | `问题介绍｜注：此栏目用于…` |
| **③ 正文区 + 评分表拼在一张表里** | 同一张表前半是填写栏，后半是打分表 | 前 6 行是填写栏，第 7 行起是"教师评价" |
| **④ 纯段落结构** | 压根没有表格，正文写在一串段落里 | 靠"主要内容："这类锚点定位 |

**只有 ① 能可靠自动识别。** 其余三种任何启发式都会在某一门上猜错，
而猜错的代价是**静默地把正文写进评分表**——比找不到更糟。

还有两类**不是正文区、却长得很像正文区**的东西，先认清再动手：

- **封面 / 表头字段**（`姓　名：____`、题目表）→ 只能"填值"，见第六节；
- **框里嵌着的表格**（题目表、信息表）→ 不能清空它所在的格子，见第七节。

⚠️ **判断列数必须用去重后的格数。** python-docx 的 `row.cells` 会把横向合并的
单元格重复返回，一张 2 列的表能被算成 9 列。判断"是不是单列"要用
`docx_kit._effective_cols()`（内部按 `w:tc` 去重），不要用 `len(table.columns)`。

### 四步流程

```
勘察 survey()  →  显式指定 Target  →  写入前 check()  →  写入后 finish() 比对
```

绝不能跳过任何一步。

## 二、第一步：勘察

```python
import sys; sys.path.insert(0, 'scripts')
from docx import Document
import docx_kit as K

d = Document('模板.docx')
print(K.survey(d))
```

`survey()` **不做判断，只摆事实**：每张表的行列数、有无边框、每行的标签与字数，
并标出「近乎为空」的格子和「疑似评分表」；**内嵌表格也会单独列出来**（标签里带
`内嵌表[0]`，看得到它嵌在哪一行哪一格）。

```
文档勘察：4 个顶层段落、2 张顶层表格、1 张内嵌表格

TABLE[0]  3行 × 2/4/6列  无边框
    row0   5字「实验名称：」 | 13字「实验一 Linux编程环境」   ⬅ 近乎为空
    row1   7字「班    级：」 | 0字(空) | 6字「姓   名：」 | 0字(空) …   ⬅ 近乎为空

TABLE[1]  7行 × 1列  无边框  单列长表（可被 find_frame 自动识别）
    row0   61字「一、实验目的：1、掌握vim编辑器的使用2、」
    row2   8字「三、题目信息」
    row4   254字「五、实验结果与分析（含程序、数据记录及分析和…」
    row6   7字「七、教师评语：」

TABLE[1] row2 col0 内嵌表[0]  2行 × 2列  带边框  [!] 内嵌表格 —— 不要清空它所在的格子
    row0   3字「题　目」 | 0字(空)
    row1   5字「指导教师」 | 0字(空)
```

**怎么读这份勘察：**

- `× 2/4/6列` 表示各行格数不一致 —— 这是**合并单元格**造成的，实际是"表单 + 合并块"。
- **结构固定、带冒号标签的格子**（`实验名称：`、`姓　名：`）多是封面信息，不是正文区；
  不带冒号的整格标签（`题　目`）同样是，值在右邻格。
- 标着 **⬅ 近乎为空**、或只有一句"注：此栏目用于…"占位说明的格子，才是留给你的。
- 标着 **⚠️ 疑似评分表** 的表，**任何情况下都不要往里面写正文**。
- 标着 **内嵌表[·]** 的，是框里的题目表/信息表：要填它的字段走 `fill_cover()`，
  要往它附近写正文走 `Target.after()`，**别清空它所在的格子**。

### 没有表格时

`survey` 会直接说明这是**段落式模板**，并提示用锚点定位。这类模板的正文区
通常在某个提示句之后——找出那句提示（如 `主要内容：`、`（正文不少于2000字）`）
作为锚点。

## 三、第二步：显式指定写入目标

**不要猜，直接指名。** 三种形态对应三种 `Target`：

```python
import docx_kit as K

K.Target.cell(table=1, row=3, col=0)   # 往 TABLE[1] 的 row3 追加（形态 ①②③）
K.Target.after('主要内容：')            # 在含该文字的段落后插入（形态 ④）
K.Target.at_end()                      # 追加到文档末尾
```

`find_frame(doc)` 仍然可用，但它**只返回单列长表**（形态 ①），认不出来就返回空列表。
它是在替你守着"宁可让你去指定，也不要猜一个出来"这条线——**看到它返回空，
不要去凑合选一个多列表，去 `survey()` 里自己找。**

## 四、第三步：写入前检查（**强制自动**）

```python
cur = K.Cursor(doc, K.Target.cell(1, 3), keep_paras=1)
cur.put(K.heading(1, '1. …'))     # ← 首次 put() 自动跑检查，拦到就抛错
```

**不需要你记得调用**——`check_target()` 在第一次 `put()` 时自动执行。
拦下时**文档一个字节都没动**（清空目标格推迟到检查通过之后），
中途放弃不会留下半个被清空的模板。

确实判断是误报时显式放行，且**必须给理由**：

```python
cur.force('人工确认这里是自评栏，允许写入')   # 不给理由直接报错
```

`check()` 拦这几类真正的危险：

| 拦截 | 判据 | 为什么危险 |
| --- | --- | --- |
| **目标落在评分/评价行或评分区** | 目标行及其上方 3 行内含 ≥2 个评分类关键词；或目标行位于 `_rubric_start()` 认定的评分区内 | 往评分表里塞正文，交上去就废了 |
| **目标落在封面/表头信息行** | 目标行或目标格含姓名/学号/题目/课程… 这类标签；`Target.after()` 的锚点也一并检查 | `put()` 会连标签带下划线一起清掉（第六节） |
| **目标格里有内嵌表格** | 目标格的直接子元素含 `w:tbl` | 清空会把表格顶到格子最前、删掉表格上方的段落（第七节） |
| **锚点落在评分区** | `Target.after()` 的锚点在评分行或评分区内 | 会在评分表内部插入内容 |
| **`at_end()` 落在评分表之后** | 文档最后一个块是疑似评分表 | 正文被写到评分表后面，版式直接坏掉 |
| **目标格已有相当多内容** | > 60 字 | 那多半是模板原有内容，写进去就覆盖了 |

评分判断是**按行**做的，不是按表：有的模板把"填写栏"和"教师评分表"做在同一张表里，
整表判断会误伤前半部分。

封面字段不是不能填，而是**不能用 `put()` 填**：改用 `fill_cover()` / `fill_field()`，
只改值，标签、下划线、封面图一字不动（见第六节）。也不要为了对齐把标签里的全角空格
改成普通空格。

`keep_paras` 控制清空目标区时保留几段（通常是 1——留住模板本来就有的那句
"四、基础实验步骤与结果："）；`Cursor(..., clear=False)` 则**完全不清空**，只追加。

⚠️ `Target.cell(table=N)` 里的 `N` 只数**顶层表格**——内嵌表格没法用 `Target.cell()`
指到，那本来也不该往它所在的格子里写（第七节）。

## 五、第四步：写入后比对

```python
cur.put(K.heading(1, '1. …'))
cur.put(K.body(caps, '……'))
report = cur.finish()
```

`finish()` 做**两道**比对：

1. **表格结构指纹**（每张表的行数、每行格数、每格字数、有无边框），
   **递归到内嵌表格**——题目表、信息表被动了同样会报出来；
2. **保护区 XML 哈希**（字节级）——见下一节。

正常时只报目标格：

```
['TABLE[1] row3 各格字数 [12] → [480]']
```

出现别的条目就是模板被动过了：

```
['TABLE[1] 行数变了：5 → 4']                       ← 表格结构被破坏
['TABLE[0] row2 各格字数 [4, 18] → [4, 16]']        ← 动了不该动的格子
['TABLE[1] row2 col0 内嵌表[0] row0 各格字数 …']    ← 题目表被动过
```

**这一步不依赖任何猜测**，是模板安全的最后一道闸。它抓的是结果，不是意图——
前面几步都判断对了它报平安，前面判断错了它也能把事故拦在交付之前。

### 保护区：连空格和换行都不许动

字数比对有个盲区：把 `姓　　名：` 改成 `姓名：`、在评分表里多敲一个空格、删掉一个
空行，字数可能只差几个甚至不变，但排版已经变了。所以 `finish()` 还会对下列元素
做 **XML 字节哈希**，任何改动都会报出来：

| 保护区 | 范围 |
| --- | --- |
| 顶层段落 | 模板原有的每一段（含其中的空白与换行） |
| 表格 | `tblPr`（边框等）、`tblGrid`（列宽）、每一行的 `tr` |
| 目标格 | 只放行目标 `tc` 的**内容**；它的 `tcPr`（宽度、底纹、合并）仍受保护 |
| 节属性 | 页边距、纸张大小 |
| 独立部件 | 页眉、页脚、样式表、编号定义（按 XML 字节哈希） |

写入过程中**新增**的段落、表格不算改动（那正是要做的）；只保护写入前就存在的元素。
`finish()` 报告里出现"封面/评分表/模板原有内容被改动"，一律回滚，不要用"只差一个
空格"说服自己放过——老师看到的就是版式被重排过。

## 六、封面与表头字段：只能填值

封面（以及题目表、学生信息表里的「姓　名：____」「题　目」）**不是正文编写区**。
`Target.cell()` + `put()` 对它是灾难：`put()` **先清空整格**，写下去以后标签、下划线、
校徽、框线一起没。

### a) 识别

```bash
python scripts/docx_env.py --cover 模板.docx     # --plan 里也带一份
```

或 `K.cover_fields(doc)`（**只报告、不改动**，有测试盯着这条）。每个字段是：

| 键 | 含义 |
| --- | --- |
| `label` | 归一化后的标签：`姓　　名` → `姓名`（全角空格不算） |
| `value` | 当前值。**空 = 还没填**；只留一串下划线的也按"空"算 |
| `where` | 位置，如 `TABLE[0] row1 col0 →下一格`、`段落0` |
| `kind` | 值该落在哪，见下表 |
| `para` | 值的目标段落（`manual` 时为 `None`） |

| `kind` | 什么情况 | 值的落点 |
| --- | --- | --- |
| `inline` | 标签和值在同一段（`姓　名：____`） | 标签段本身，标签之后 |
| `next_para` | 标签独占一段，值留在下一段 | 下一个空白段落 |
| `next_cell` | 标签独占一格，值是右邻格（**题目表最常见**） | 右邻格首个段落 |
| `manual` | 找不到可靠的落点 | **不动**，交人工 |

标签的两种写法都认：`姓　名：`（带冒号）和 `| 题　目 | 值 |`（不带冒号、值在右邻格）。

### b) 问用户

把「待填」清单原样发给用户，让他选：**报值给你 / 他自己在 Word 里手填 / 只填其中几项**。
**绝不猜**姓名、学号、日期。用户说自己手填，就一个字都别动封面，交付说明里写明
"封面字段留空待填"。

### c) 填值

```python
before = K.snapshot(d)
filled, missed, manual = K.fill_cover(d, {'姓名': '张三', '学号': '00000000'})
assert not K.diff_structure(before, K.snapshot(d))   # 结构必须零变化
```

`fill_field()`（`fill_cover` 内部就是它）的取值顺序：

1. 标签后本来就有空白 run（下划线 / 空格）→ **只改它的文字，格式原样保留**；
2. 标签后已有内容 → 替换那一部分，**标签一字不动**；
3. 标签后什么都没有 → 追加一个 run，字体字号照抄标签（去掉加粗）。

实测过的细节：

- 标签被拆成「姓」「　」「名」「：」四个 run 也不怕——`_tail_runs()` 先按**字符**定位
  标签结束的位置，必要时切开 run，绝不会误伤标签本身。
- `＿＿＿＿` 由两个 run 拼成时，只填第一个、其余清空，值不会跑到下一格去。
- 已经填好的值（`实验名称：示例课程实验`）再填一次是**替换**，不会变成拼接。
- `underline=True` 才强制加下划线；默认 `None` = 模板什么样就什么样。
- ⚠️ `w:u` 在 `w:rPr` 里必须排在 `sz` **之后**、`vertAlign` **之前**，位置错了 Word
  报"文件内容已经损坏"（`_ensure_underline()` 已处理）。

### d) 查

`missed` = 给了值但没找到对应字段；`manual` = 找到了但落点不可靠。
两个非空都别硬塞——回去问用户或让他手填，并在交付说明里写明哪几项留空。

封面图、校徽、下划线长度、页面边框、封面所在的节与分页符：**一律不动**。

## 七、框里的内嵌表格（题目表格）

模板除了最外面那个框，**框内常常还嵌着表格**：题目表、学生信息表、小组成员表，
有的连评分表也做在框里。它们和框一样是模板原有内容。

### a) 一定要能看见它们

`survey()` / `--plan` 会标出来，标签自带位置：

```
TABLE[1]  3行 × 1列  带边框  单列长表（可被 find_frame 自动识别）
TABLE[1] row1 col0 内嵌表[0]  2行 × 2列  带边框  [!] 内嵌表格 —— 不要清空它所在的格子
    row0  「题　目」 | 0字(空)
    row1  「指导教师」 | 0字(空)
```

`K.nested_tables(doc)` 只取内嵌的那批。**结构指纹也含它们**——`snapshot()` /
`finish()` 走 `iter_tables()` 递归到每一层，内嵌表格的行数、每格字数、边框被动过都会
报出来。（只看顶层表格的做法会漏掉这类破坏，别退回去。）

### b) 别清空内嵌表格所在的格子

`put()` 会先清空整格。格子里嵌着表格时，清空 = **表格上方的段落全没了、表格顶到
格子最前面**，版式直接毁掉。`check_target()` 专门拦这一种：

```
目标格 TABLE[1] row1 col0 里内嵌了 1 张表格（题目表/信息表最常见）。
put() 会先清空整格：表格上方的段落会消失、表格被顶到格子最前面。
改用 Target.after("表格附近的锚点文字")，或 Cursor(..., clear=False) 追加。
```

### c) 往这种区域下笔的三种正确姿势

| 想做什么 | 怎么写 |
| --- | --- |
| 内容加在表格前后的某句提示之后 | `K.Cursor(d, K.Target.after('三、题目信息'))` |
| 只是往这一格追加，不动原有内容 | `K.Cursor(d, target, clear=False)` |
| 要**填**表里的字段（题目、指导教师…） | `K.fill_cover(d, {'题目': '…'})` |

锚点段落就在单元格里也没关系：`Target.after()` 按全文检索段落，`addnext()` 插在段落
之后；收尾时 `finish()` 会往上找最近的单元格，必要时补一个 1pt 段落（单元格不能以
表格结尾，见 `docx-cookbook.md`）。

### d) 验收

```python
before = K.snapshot(d)
... 写入 ...
rep = cur.finish()
assert not [r for r in rep if '内嵌表' in r]      # 内嵌表格一个字都不该变
```

## 八、提取"需编写区域"的格式

**只提取要写的那块，不要动模板其余部分。**

要看的：

| 项 | 在哪看 |
| --- | --- |
| 字体、字号、加粗、颜色 | 该单元格里**模板自己写的**段落的 run |
| 段落样式名 | `w:pStyle`（如 `Caption` 题注样式） |
| 首行缩进 | `w:ind firstLineChars` / `firstLine` |
| 段前段后、行距 | `w:spacing` |
| 标题层级风格 | 小标题是加粗？黑体？放大？还是跟正文同款 |

**关键：拿模板自己已有的段落当基准，别拿自己的第一版当基准。**

### 只对齐"需编写区域"

模板里的评分表、已有的实验目标、封面上的固定文字——这些都不需要你写，它们的格式
**原样跳过**。写一份报告不需要让整篇文档风格统一，只需要让**你写的那部分**贴合模板。

封面字段是例外中的例外：它们的"值"要填，但**格式不归你定**——用的是模板自己留的
那个空白 run（第六节）。所以封面根本不在"提取格式"的范围里。

### 段前段后不要自己加

插入的段落不要带 `w:before` / `w:after`，让它继承 Normal 样式。写了显式间距，用户一眼就看出来"这不是模板的样式"。

## 九、模板里放的是"格式说明"时

有些模板的正文不写内容，写的是：

```
正文              宋体 小四 1.5倍行距
二级标题          黑体 四号
图表题注          宋体 五号 居中
```

或者干脆是"正文字体 XXX、字号 XXX"这样的说明。

**这种情况严格照它说的做**——比任何推测都权威。照做之后在交付说明里点一句"按模板中的格式说明设置"，方便用户核对。

## 十、样式名不要想当然

**同样是"实验报告模板"，不同实验的模板可能完全不同。**

实际遇到过的：一个模板里 `Caption`（题注）是段落样式、`styleId="a4"`；另一个模板里 `a4` 是**字符样式**「页眉 字符」，根本没有 `Caption` 段落样式。照抄前一份报告的 `pStyle` 值就会静默套错样式，而且不一定报错。

动手前先列样式表：

```python
for s in doc.styles:
    print(s.style_id, s.type, s.name)
```

要用的样式不存在时，往 `d.styles.element` **追加**一个（只增不改，不破坏模板），同时给每个 run 写上显式字体字号——这样即使样式被丢弃，外观也不会变。

## 十一、老式 `.doc` 模板的处理

python-docx 打不开 `.doc`，先转：

```bash
powershell -File scripts/word_com.ps1 -Action to-docx -In 模板.doc -Out work.docx
```

编辑完再转回去：

```bash
powershell -File scripts/word_com.ps1 -Action to-doc -In out.docx -Out 报告.doc
```

⚠️ `.docx` 存回 `.doc` 会丢一些元数据（`w:rFonts w:hint="eastAsia"`、`w:tblInd`、几个样式定义被重新规范化）。这些**不可避免且不可见**，不要试图消除。

判断"模板有没有被我破坏"的正确方法：把原始模板也走一遍同样的往返，比较两者的 XML 差异集合；**差异集合一致**即视为没破坏，而不是要求差异为零。

`w:trHeight`（框每行的最小高度）是**会**保留的——如果框的行高明显丢了，那才是真的把表格重建了。

## 十二、记下交付格式：跟模板走

解析模板时顺手把**扩展名**记下来，它决定最终产出什么：

| 模板 | 交付 |
| --- | --- |
| `xxx-模板.doc` | **必须**产出 `.doc` |
| `xxx-模板.docx` | 产出 `.docx` |

中途为了用 python-docx 编辑，`.doc` 会先转成 `.docx` —— **但那份 `.docx` 只是中间产物，不是成品**。交付前一定转回去：

```bash
powershell -File scripts/word_com.ps1 -Action to-doc -In out.docx -Out 报告.doc
```

格式和模板不一致，老师那边很可能打不开或者版式错乱，这是很低级的失分点。

## 十三、工作目录

**所有中间产物写在报告所在目录下**——工作副本 `work.docx`、构建脚本 `build.py`、压缩后的图片副本、导出的 `preview.pdf`。用户一眼能看到全过程，相对路径也不会突然失效。

只有确实遇到绕不过去的权限问题（目录只读、被同步盘锁住）才退到系统临时目录，并在交付时说明中间产物放在哪。
