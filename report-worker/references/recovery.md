# 失败、回滚与断点续跑

## 失败分层

| 层 | 例子 | 处理 |
| --- | --- | --- |
| 动作失败 | 命令非 0、窗口找不到、点击没变化 | 按步骤失败分支重试，最多 3 次 |
| 步骤验收失败 | 输出不匹配、文件没生成、画面不对 | 先修环境/配置，再重做该步 |
| 证据失败 | 缺字段、模糊、对应错步 | 只补拍缺口，不重做整场 |
| 报告失败 | 缺要求、分析浅、格式错 | 回 writer，不重跑实验 |
| 计划失败 | 目的没覆盖、步骤缺证据 | planner 升版，用户确认 |
| 审核误报 | 位置不存在/依据不成立 | 标 `需人工复核`，不改 |

## 重试

- 单步最多 `max_step_attempts`（默认 3）；
- 每次重试换一种策略：换控件名、换键盘、换坐标、换命令写法；
- 不要把同一条命令原样跑 3 次；
- 失败现场保留（截图/日志），它可能是报告“问题与解决”的素材。

## 备份与回滚

改文件前：

```bash
python scripts/actions.py --workspace <WS> snapshot --path <文件>
```

- 备份到 `_worker/backups/<时间戳>/`；
- 记录 SHA256；
- 需要回滚时从备份复制回去，并在 `state.history` 记一笔；
- 网络/系统配置先存基线（如 `running-config`、`ovs-vsctl show`）；
- 代码优先用 git 快照；没有 git 就用文件备份。

## 断点续跑

0. 先 `worker.py doctor`（崩溃/中断后必做）；有残留动作先看 `actions.py list --json`，
   用 `actions.py resolve` 标记，不要直接重跑；
1. `worker.py status` 看阶段；
2. `worker.py next` 看下一步；
3. 读 `_worker/roles/*.result.json` 看上一个角色做到哪；
4. 读 `_worker/actions.jsonl` 看最后动作；
5. 从正确状态继续，不要从头重来。

状态文件损坏：

- 从 `_worker/backups/` 找最近的 `state.json`（如果有）；
- 没有就 `init --force` 重建，但会丢历史；先向用户说明。

## 计划变更

- 设备/软件更换、老师加要求、步骤删减、数据不足、分组变化 → 计划升版；
- 先判断旧证据是否仍有效；
- 只补缺口或重做受影响步骤；
- 不覆盖旧版；在版本记录写清原因；
- 影响实验目的/交付要求的变更，必须用户确认。

## 预算

- 动作数、墙钟时间、报告轮次都有上限；
- 接近上限时先停下来汇报，不要偷偷超预算；
- 超预算/权限/环境阻塞 → `BLOCKED`，列明用户下一步要做什么。

## BLOCKED 报告模板

```markdown
# 阻塞报告

- 阶段：<phase>
- 已尝试：<动作/命令/窗口/重试次数>
- 卡在哪：<错误/缺失/权限/环境>
- 为什么不能自动修：<原因>
- 需要用户做：
  1. ...
  2. ...
- 相关文件：<日志/截图/状态>
```
