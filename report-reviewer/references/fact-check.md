# 事实核对：时间线、归属、机制、过度概括

内容“看起来顺”不等于事实可靠。这一遍专门查**说法是否准确、是否过度概括**。

## 一、时间线

同一组人物/算法/事件在不同位置出现时，顺序和年份必须一致：

- 摘要、正文、结论、表格四处逐一对照；
- 一旦发现顺序不一致，以原始论文/教材为准统一；
- 例（决策树）：

| 算法 | 年份 | 归属 |
| --- | --- | --- |
| AID | 1963 | Morgan & Sonquist |
| CART | 1984 | Breiman et al. |
| ID3 | 1986 | Quinlan |
| C4.5 | 1993 | Quinlan |

不要写成“ID3 → CART → AID”或把 CART 放到 1990 年代。

## 二、算法归属与年份

逐项核对：

- 谁提出的、哪一年、发表在哪里；
- 剪枝方式（预剪枝/后剪枝）属于哪个算法；
- 缺失值处理机制（如 C4.5 的缺失值按权重分配）不要张冠李戴；
- 分裂准则（信息增益 / 增益率 / 基尼指数）与算法对应正确。

不确定时改为：

- “通常认为……”
- “多数实现……”
- “相关综述认为……”
- “据……（年份）的原始论文……”

## 三、机制描述

重点查这些容易写错的：

- SLIQ 的“驻留内存的属性表”表述是否准确（属性表/类表各驻留什么）；
- 剪枝发生在建树前还是建树后；
- 连续值离散化、缺失值分支、多叉/二叉的差异；
- 集成方法（Bagging/Boosting/随机森林）的样本与特征采样方式。

## 四、过度概括与绝对化

| 不要写 | 改为 |
| --- | --- |
| “白皮书显示树集成最成熟、部署成本最低” | “相关产业报告普遍认为树集成是成熟度较高、部署成本较低的方案之一” |
| “深度森林在推荐广告中常用” | “深度森林在部分推荐/广告场景有应用报告” |
| “决策树对异常值不敏感” | “决策树对异常值相对不敏感，但并非完全免疫” |
| “某算法一定优于……” | “在……条件下，某算法通常表现更好” |

保留引用来源；没有来源的产业结论，宁可写“据相关报告”并补引用，不要写成定论。

## 五、一致性

- 全文同一概念只有一种写法（如“AI 漫剧”不要与“AI 漫画”混用）；
- 结论与数据不矛盾（正文说“仅 1055 部破亿”，结论不能写“爆款频出”）；
- 单位、数量级、百分比口径一致；
- 图表标题、正文、结论中的数字一致。

## 六、输出方式

事实核对发现的问题单列【事实/表述问题】，每条写：

- 位置（章节/段落）；
- 原文；
- 问题类型（时间线/归属/年份/机制/过度概括/前后不一致）；
- 建议改法；
- 依据（论文/教材/报告，尽量给年份）。

**不要把它和【正确性错误】混在一起**：后者是明确错误，前者是“说法不够严谨”。
