# 材料检索与命名惯例

写报告前要先在目录里找到**模板、指导书、参照用的成品报告**。这些东西的位置和命名
在不同课程之间差别很大，只按想当然的关键字搜一定会漏。下面是从多门课程的实际目录里
归纳出来的规律。

## 一、最重要的结论

### README 里通常没有报告规范

课程仓库的 README 往往只列"包含 N 次实验 / N 次作业"，**不写任何格式规范**。

→ **报告规范基本都在模板文件本体里**（正文框 + 评分表 + 可能印着的格式说明）。
"解析模板"这一步不能省，也不能靠读 README 代替。

### 老式 `.doc` 仍然占相当比例

不少课程的模板与成品都是 `.doc`。Word COM 是主路径，`python-docx` 读不了 `.doc`。
详见 `docx-cookbook.md`。

## 二、检索：别只按"模板"两个字找

模板的位置和命名都不固定，只按关键字搜会漏。

| 陷阱 | 表现 | 对策 |
| --- | --- | --- |
| 模板不在实验子目录，而在上一层 | `Experiments/xxx-实验报告模板.docx` | 两级都要扫：`Experiments/*` 和每个 `Experiment_NN/*` |
| 文件名**不含**"模板" | 就叫 `实验报告1.doc` 的裸名文件 | 看到"实验报告N"且体积明显小于成品，就当模板处理 |
| 模板与"要求"**合并成一个文件** | `…模板与要求.docx` | 搜"模板"时同时搜"要求" |
| 用"题目"而非"指导/要求"命名 | `实验一 题目.docx` | 搜 `题目` / `指导` / `要求` / `说明` 四个词 |
| 附带大部头手册 | 几 MB 的用户手册、规范 PDF | 只要文件名，别读内容 |

**调研阶段只取文件名、大小、目录结构。** 成品报告动辄十几 MB（内嵌截图），
PDF 手册也有好几 MB，读它们的二进制没有意义，还会撑爆上下文。

## 三、成品报告命名：不要假设有统一规则

**命名惯例因课程而异，同一门课里也可能漂移。** 实际见过的写法包括：

```
<学号>_<姓名>_实验一.docx        下划线 + 中文数字
<学号>-<姓名>-实验1.doc          连字符 + 阿拉伯数字
<学号> <姓名> 实验报告1.doc      空格分隔
<学号><姓名>.doc                 完全无分隔符，且不带实验号
<学号>_<姓名>_×4人_《课程》实验一.doc    小组，学号姓名重复多组
<项目名>+<姓名> <姓名>.docx      小组，用 + 连接
```

### 从文件名反推不出实验号

有的成品名里根本没有实验号。**以父目录 `Experiment_NN` 为准**，别解析文件名。

### 同一门课里可能重名

不同目录下的成品可能有**完全相同的文件名**（例如某课程 `Experiment_01/` 与
`作业目录/` 下同名）。任何按文件名去重/匹配的操作都会误伤——**要带上目录路径判断**。

### 模板占位符怎么替换

模板名里的占位符在实际交付时被整体换掉，并**去掉"-模板"后缀**：

```
模板： 学生-姓名-实验报告1-模板.doc
交付： <学号>-<姓名>-实验报告1.doc
```

## 四、报告类型不止"实验报告"

先判断这次到底是哪一类，不同类型的要求差别很大。

| 类型 | 特征 |
| --- | --- |
| **实验报告** | 有实验目录、指导书、模板、操作截图 |
| **研读报告 / 文献综述** | 无实验过程，围绕一份材料或一个主题展开，**必须带参考文献** |
| **课程报告** | 整门课一份，可能按学期/等级分层存放，不是按实验编号 |
| **PPT 汇报作业** | 交付物是 `.pptx` 而非文档，模板也是 PPT |
| **数据驱动型实验报告** | 报告由脚本生成，图表多、需要交叉引用 |

写之前先归类——拿实验报告的路子去套 PPT 汇报，方向就错了。

## 五、扩展名：逐份判定，不要按课程一刀切

**同一门课里可能混用 `.doc` 和 `.docx`**（例如早期实验是 `.doc`、后期转成了 `.docx`）。

→ "产出格式与模板一致"这条规则要**逐个实验单独判定**，以该实验目录下那份模板的
扩展名为准，不要按课程统一。

## 六、组队模式差异大

单人 / 3 人 / 4 人小组都有，命名与"同组成员"字段的填法各不相同。

**别自作主张**：先看同目录有没有成品报告可参照；拿不准就直接问用户。

## 七、目录状态要先判定

课程仓库里普遍存在 `.gitkeep` 占位的空实验目录，"有模板但没成品"也很常见。

| 状态 | 处理 |
| --- | --- |
| 有模板、有成品 | 正常写。成品**只用于参照格式**，内容自己写 |
| 有模板、无成品 | 正常写 |
| 目录全空 | **如实告知用户没有可用素材**，请其提供指导书与模板；不要凭空编造 |

## 八、判断"模板还是成品"：看内容，不看文件大小

⚠️ **别用文件大小猜。** 实际遇到过两份文件**字节数完全相同**，但 MD5 不同、
内容也完全不同——一份是空白模板，另一份是写得很完整的成品报告（两份同源于一个模板，
内嵌了相同的样式与图片资源，所以体积一样）。

判断方法很简单：

```bash
# 1) 先看哈希：哈希相同才是真同一份文件
md5sum "候选A.doc" "候选B.doc"
# 2) 哈希不同就转出来读内容（成本很低）
powershell -File scripts/word_com.ps1 -Action to-docx -In 候选.doc -Out 临时.docx
python scripts/docx_env.py --describe 临时.docx
```

正文框里只有标题和占位符 → 是模板；有整段正文和分析 → 是成品。

**成品体积异常小**（几十 KB）时反而要留意：可能是写完但没插图的半成品。

## 九、动手前的检索清单

```bash
ROOT="<课程目录>"
# 1. 实验/作业目录
find "$ROOT" -maxdepth 2 -type d -not -path "*/.git*" | sort
# 2. 每个目录里有什么（看文件名和大小就够了）
find "$ROOT" -type f -not -path "*/.git*" -printf "%10s  %p\n" | sort -k2
```

拿到清单后逐项归类：

- [ ] 本实验的**模板**是哪份？（两级目录都扫，别只看名字含"模板"的）
- [ ] **指导书/题目**是哪份？（搜"指导""要求""题目""说明"）
- [ ] 有没有**同课程成品报告**可参照格式？（注意同名文件，以及"看着像模板其实是成品"的情况）
- [ ] 图片/数据在哪？（`Pictures/` 的组织与命名也不统一）
- [ ] 本次要交**什么格式**？（以本实验模板的扩展名为准）
- [ ] 单人还是小组？小组成员是谁？
