# 实验执行卡模板（默认产出 / 即开即用版）

> 本文件是**即开即用版**：现场照着做。
> 详细全面版见 `实验规划书.md`，用于确认细节和交给 `report-writer`；它不是课程指导书。
>
> 目标：同学打开就能从第一行照着做。
> **开头先给实验目标和阶段目标**，不要先写环境/端口/日期检查；这些放到末尾的
> 「开做前检查」。每一步都要有"这一步要达成什么"和"做完看到什么"。
> 长度：2~4 页；截图速查 1 页以内。

## 关键写法

### 开头写"步骤 → 预期结果"，不写泛泛目标或检查清单

| 差 | 好 |
| --- | --- |
| 开头：一段"做完实验应得到……"的目标描述 | 开头：一张"步骤 / 预期结果 / 截图"速查表 |
| 开头：检查端口、检查环境、检查日期、检查文件夹…… | 开做前检查放末尾，开头只留一句"开做前检查见 §5" |
| 第 0 节和后面的步骤表内容重复，删掉也没区别 | 第 0 节是全流程速查，能一眼看出 8~12 个关键节点和验收结果 |

**判断第 0 节有没有用**：如果删掉它，学生仍然知道"先做什么、做到什么算完成"，
说明它只是重复；好的第 0 节应该让学生不用翻后面的表，就能知道整场实验的骨架。

### 每个阶段要有目标

阶段目标回答："这个阶段做完，我手上多了什么？"

| 差 | 好 |
| --- | --- |
| "阶段一：准备" | "阶段一：准备（目标：得到可运行的拓扑脚本和四台主机 IP）" |
| "阶段二：基础实验" | "阶段二：基础实验（目标：抓到并解释 OpenFlow 1.0 的 Packet-In / Flow-Mod）" |
| "阶段三：进阶实验" | "阶段三：进阶实验（目标：抓到 1.3 握手、流表前后和三类报文）" |

### 每一步要有"步骤与目标"

不要只写"做什么"，要写"这一步达成什么"。

| 差 | 好 |
| --- | --- |
| "配置 IP" | "配置四台主机 IP——让主机同网段二层互通，避免引入三层转发" |
| "抓包" | "抓 Packet-In——找到触发上送的那条报文，为解释 table-miss 做准备" |
| "看流表" | "查看 ping 前流表——确认当前只有 table-miss，作为前后对比的基线" |

### "达成效果"必须可观察

| 差 | 好 |
| --- | --- |
| "配置成功" | "`show vlan brief` 显示 port1/2 在 VLAN 10，port3/4 在 VLAN 20" |
| "运行正常" | "终端出现 `listening on 8080`，客户端收到 200 响应" |
| "数据正确" | "12/12 收到应答，丢包率 0%" |

### 截图提示要具体

| 差 | 好 |
| --- | --- |
| "截一张图" | "E8：Wireshark 选中 Packet-In，展开报文树，必须看到 Version/Type/Length/Buffer ID/Reason" |
| "截图记录结果" | "E4：只截 `dump-flows` 的命令 + 关键输出行，必须含 priority、match、actions、n_packets；不要整屏" |
| "截配置页" | "E3：截配置页 + 顶部设备名/版本，红框标出目标接口" |
| "把整个 IDE 截进来" | "只截改动的那段代码 + 文件名/行号；完整代码用文本块" |
| "截整个终端" | "只截命令 + 结果 + 提示符；无关历史滚出画面" |

### 绘图要求不算用户截图

| 差 | 好 |
| --- | --- |
| 执行卡写"画基础流程图" | 执行卡写"记录 packet number / 报文顺序，供 writer 画流程图" |
| 截图清单里放"流程图 E11" | 截图清单只放原始证据；流程图列在 §4「writer 需要绘制的图」 |
| 要求用户画架构图/SWOT 图 | 用户提供拓扑截图/数据；writer 根据证据绘图 |

### 卡住怎么办只写"先查什么"

| 差 | 好 |
| --- | --- |
| "重新做" | "先 `pingall` 看丢包位置；再 `ovs-vsctl show` 看链路；最后看控制器日志" |
| "检查配置" | "检查 IP 是否同网段、接口是否 up、默认网关是否误填" |

## 示例：网络配置实验（节选）

```markdown
## 0. 实验目标与流程总览

**做完这份实验，你应该得到：**

- 一个可运行的 VLAN + 单臂路由拓扑
- 配置页、验证输出、失败现场三组截图
- 一张"同 VLAN 通 / 跨 VLAN 通"的对比表

| 阶段 | 阶段目标 | 关键步骤 | 预计 |
| --- | --- | --- | --- |
| 准备 | 拓扑和基线配置就绪 | S1-S3 | 10 min |
| 执行 | VLAN/Trunk/单臂路由配置完成 | S4-S7 | 35 min |
| 验证 | 连通性符合预期，有成功/失败对比 | S8-S10 | 15 min |
| 收尾 | 配置/日志/截图齐全 | S11 | 5 min |

## 1. 截图速查卡

| ID | 什么时候拍 | 拍什么 | 必须包含 | 文件名 |
| --- | --- | --- | --- | --- |
| E1 | 操作前 | 设备版本 + 基线状态 | 设备名、版本、接口状态 | `S1_基线.png` |
| E2 | 配置后 | VLAN/接口配置 | 接口名、VLAN、状态 | `S2_VLAN配置.png` |
| E3 | 验证时 | ping/连通性结果 | 命令、源/目的、成功率 | `S3_验证.png` |
| E4 | 失败时 | 报错/异常 | 完整报错、操作步骤 | `S4_报错.png` |

## 2. 照做清单

### 阶段一：准备（目标：得到可回退的基线配置）

| # | 步骤与目标 | 具体操作 | 达成效果（验收） | 截图/记录 | 卡住怎么办 |
| --- | --- | --- | --- | --- | --- |
| S1 | 记录环境——知道后续配置在什么版本上验证 | `show version`、`show ip interface brief` | 型号/版本/接口状态都能读到 | E1：版本 + 接口状态同屏 | 检查 Console/SSH、权限 |
| S2 | 备份配置——出问题能回退 | 复制 running-config 到备份文件 | 备份文件存在且能打开 | E1b：备份路径/文件名 | 检查磁盘/权限 |
```

## 生成后的自检

- [ ] 第 0 节是"步骤 / 预期结果 / 截图"速查表，不是泛泛目标或检查清单
- [ ] 第 0 节删掉也说得通吗？如果说不通，说明它只是重复，需要改成真正的速查
- [ ] 每个阶段都写了"完成后得到什么"，并有"阶段验收"
- [ ] 每一步都有"步骤与目标"，不是只有"做什么"
- [ ] 每一步都有可观察的"达成效果"
- [ ] 每一步都有截图/记录提示，或明确写"无截图，记录数据/日志"
- [ ] 截图提示写清了"必须包含什么"，不是"截一张图"
- [ ] 卡住怎么办只写先查什么，详细排错在末尾
- [ ] 开做前检查放在末尾，不占开头
- [ ] 有"截图验收（分阶段提交）"说明：按执行卡阶段分组，默认 `Pictures/`
- [ ] 没有把流程图/示意图放进用户截图清单；已列入 writer 要画的图
- [ ] 执行卡 2~4 页；截图速查 1 页内
- [ ] 报告交接只写"哪节写什么、用哪些证据"，没有替 writer 写正文
